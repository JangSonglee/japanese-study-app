# 토모의 편지 · 편지함 (설계 문서)

- 작성일: 2026-07-31
- 결정자: 대표님
- 상태: 확정 (구현 계획 = writing-plans 후속)
- 관련: PRD 14.5(쪽지)·8.3(편지함)·12.2(우표), item 4 스펙 `2026-07-30-stamp-letter-pdf-economy-design.md`

## 배경 — 새 우표 모델이 남긴 공백

2026-07-30 우표 모델을 「소비형 → 컬렉션형」으로 바꾸면서 **편지가 더 이상 요약 PDF가 아니게**
됐다(우표 14장마다 오는 감성 리워드, 첫 편지 3장). 그러나 "편지가 대체 무엇인지"·"편지함은
무엇을 담는지"가 비어 있었고, PRD의 옛 정의(편지=요약 PDF)와 충돌했다. 이 문서가 그 공백을 채운다.

## 결정 사항

1. **편지 = 토모의 이정표 편지**(대표님). 토모가 보내는 담담한 손편지 — 그 기간을 조용히 회고하고,
   배운 것을 살짝 짚어준다. 개인적·회고적이라 쪽지(가벼운 격려)와 명확히 구분된다.
2. **편지함 = 받은 편지만**(대표님). 순수 감성 컬렉션. 쪽지·요약 PDF는 성격이 달라 따로 둔다.
3. **도착 신호 = 우표 위젯**(설계): 우표가 목표치에 도달하는 순간 홈 우표 위젯이 「편지 도착」
   상태로 전환 → 우표→편지 은유를 위젯에서 완결. 🔴 토모 밝아짐(헤일로)은 **「새 쪽지」 전용 유지**
   (PRD 14.2.1) — 편지엔 쓰지 않는다. 편지 도착도 폭죽·축하 없음(토모 톤).

## 콘텐츠 모델 — 편지

> **🔴 개정(2026-07-31, 대표님): 편지 본문은 「일본어」로.** 편지도 학습이 되게 — 감성 때문에 끝까지
> 읽고 싶어지는 콘텐츠라 일본어 몰입에 최적의 자리. **후리가나 기본 ON**(읽기 부담↓) + **해석 기본
> OFF**(스스로 먼저 읽되 우상단 토글로 확인, PRD 8.4 「위로받는 자리」). 기존 `Ruby` 후리가나 렌더러 +
> `rubyParse.rubyToJson` 재사용. 쪽지(짧은 한 줄)와는 「긴 개인 편지」로 여전히 구분. 아래 한국어 서술은
> 톤·구조 기준으로 유효하되, 실제 본문 언어는 일본어.

- **화자·수신**: 토모 → 학습자(예: ソンイさん). 본문 일본어(학습자 수준 N5~N4) + 한국어 해석.
- **구조**: 인사 → 그 기간 담담한 회고 → 배운 것 살짝 → 맺음(서명 "— 토모" + 날짜).
- **톤**(PRD 14.4 관찰자): 짧고 절제, 허용체("~해도 돼요"), 느낌표·수식어 최소, 재촉·판단 없음.
- **회차**: 1회차 = 첫 편지(우표 3장), 이후 14장마다. 회차마다 다른 문안.
- 🔴 **지금은 데모 문안 2~3통 + 구조.** 실 데이터(그 기간 배운 단어수·스트릭·기간) 삽입은
  인증·적립 이후. 데모 예시(톤 기준):
  - 1회차 「첫 편지예요」: "송이 님께, / 사흘째, 불을 켜러 와 줬어요. / 아직 시작이지만, 시작을
    세 번 한 사람은 많지 않아요. / 오늘 배운 말들, 제가 다 봤어요. / — 토모"
  - 2회차 「2주가 지났어요」: "송이 님께, / 2주 동안, 열네 번 함께했어요. / 동사 활용에서 자주
    멈췄는데, 요즘은 덜 멈추더라고요. 저는 봤어요. / 서두르지 않아도 돼요. 불은 계속 켜 둘게요. / — 토모"

### 데이터 구조(FE 데모)
`data/letters.js`:
```
LETTERS = [
  { id, seq, dateLabel, title, preview, paragraphs: [string...], signoff: '— 토모', unread: bool },
  ...  // 최신순
]
```
`preview` = 목록용 첫 줄 요약. `unread` = 편지함 목록에서 새 편지 표시(데모).

## 화면·인터랙션

### ① 홈 우표 위젯 — 도착 상태 추가 (`HomeScreen`)
- 데모에 `letterWaiting` 개념 추가(우표 목표 도달 = 편지 대기).
  - `letterWaiting` true → 위젯이 「편지가 도착했어요 · 열어보기」(앰버, 잔잔). 탭 → `LetterScreen`(최신 편지) → 소장.
  - false → 기존 「모은 우표 N / need · 다음 편지까지 M장」. 탭 → `LetterBoxScreen`(편지함, 지난 편지).
- 🔴 밝기 헤일로·폭죽 없음. 「도착」은 위젯 문구·앰버 톤으로만.

### ② 편지함 (`LetterBoxScreen`, 신규) — MY 탭에서 진입
- MyScreen에 「편지함」 메뉴 행 신설(학습 섹션 또는 신규 섹션).
- 받은 편지 목록: 각 항목 = 날짜 · 제목 · preview 한 줄 (+ unread면 작은 표시). 탭 → `LetterScreen`.
- **빈 상태**: "아직 토모의 편지가 없어요 · 다음 편지까지 N장" — 담담한 톤(압박·빨간점 없음).

### ③ 편지 상세 (`LetterScreen`, 신규)
- 편지지 레이아웃(디자인시스템 v3.3 토큰: 카드 lg·조판 keepAll·앰버 절제). 제목·본문 문단·서명·날짜.
- 상단 토모(평소 밝기, pose=read 또는 shine). 하단 「편지함으로」/「닫기」.
- 소장 느낌: 편지지 배경 톤, 우표 모티프 작은 장식(선택).

### 라우팅
`router.js`는 문자열 name 스택 — 신규 라우트 `letterBox`, `letter`(params: `{ id }`) 추가.
`App.jsx` 스위치에 두 화면 배선. `LetterScreen`은 `letter` 라우트가 `id`로 `LETTERS`에서 찾음.

## PRD 정합 (문서 갱신)
- **14.5 편지 vs 쪽지 표(846~848)**: 편지 행을 「토모의 이정표 편지 / 우표 14장(첫 3장) / 소장용
  감성 편지」로 갱신. 쪽지 행 유지.
- **8.3 편지함**: 「일별 요약 모아보기」 → 「토모의 편지 컬렉션」으로 재정의. 일별 세션 요약은
  세션 종료 화면·PDF로 남고 편지함엔 넣지 않음.
- **12.2**: 이미 item 4에서 갱신됨(편지=감성 리워드). 도착 신호=우표 위젯 한 줄 추가.
- 개정 이력에 반영(PRD v2.9).
