# 토모에게 답장하기 (설계 문서)

- 작성일: 2026-07-31
- 결정자: 대표님
- 상태: 확정 (구현 계획 = writing-plans 후속)
- 관련: `2026-07-31-tomo-letters-design.md`(편지·편지함), 인증 스캐폴드(`auth.uid()` RLS), PRD 14.4·14.5·8.4

## 배경

편지를 일본어 읽기 학습으로 만든 데 이어(2026-07-31), **답장 = 쓰기(작문) 학습**으로 확장한다.
대부분 앱이 입력(읽기·듣기)만 시키는데 출력(쓰기)까지 가면 학습 가치가 크다. 방금 붙은 인증
위에서 답장을 **실제로 저장**해, 편지함이 「토모의 편지 + 내가 보낸 답장」의 왕복 서신이 된다.

## 결정 사항

1. **답장 = 가이드형 일본어 작문**(대표님). 백지 자유 작문(초급 부담)이 아니라 **따뜻한 일본어 문구
   카드**를 골라 조립. 후리가나·해석으로 뜻을 알고 보냄. 한국어 자유 입력도 한 줄 허용.
2. **진짜 저장**(대표님). `letter_replies` 테이블 + RLS(`auth.uid()`). 새로고침·재접속해도 남는다.
   **로그인 필요** — 게스트는 답장 대신 담담한 로그인 안내(재촉 아님).
3. **토모는 담담히 받는다** — 억지 대화 없음. 보내면 짧은 확인(예: 「受け取りました」/"잘 받았어요")
   + 토모 read 포즈. 🔴 밝기 헤일로·폭죽 없음(토모 톤, 14.2.1).
4. **철저히 선택** 🔴 — 답장 안 해도 아무 신호·재촉·빨간점 없음. *위로받는 자리*가 *숙제*가 되지 않게(1.3·14.4).

## BE — `letter_replies` 테이블

```
letter_replies
  id uuid pk default gen_random_uuid()
  user_id uuid not null → auth.users(id) on delete cascade
  letter_seq int not null        -- 편지 회차(1,2…). 데모→실 편지에 안정적인 키
  phrase_keys jsonb not null      -- 선택한 문구 카드 key 배열(재현·분석용). 예: ["thanks","comeback"]
  body_ko text                    -- (선택) 한국어 한 줄 자유 입력
  created_at, updated_at timestamptz default now()
  unique(user_id, letter_seq)     -- 편지당 답장 1개(수정=upsert)
```
- **RLS**: 본인 것만(select/insert/update/delete `user_id = auth.uid()`). authenticated grant.
- 🔴 편지 콘텐츠(l1/l2)는 아직 FE 데모라 DB에 없다 → 답장은 `letter_seq`로 건다(회차 = 안정 키).
  실 편지 파이프라인이 와도 seq로 이어진다.
- 편지당 1답장(unique) + upsert = 수정 가능. 문구 key로 저장하고 렌더는 FE 문구 정의에서 후리가나 재현.

## FE

### 데이터 (`data/letters.js` 또는 신규 `data/letterReplies.js`)
- `REPLY_PHRASES` — 가이드 문구 카드(각 `{ key, jp(브래킷 후리가나), ko }`). 초기 5~6개(N5, 토모 향):
  - `thanks` ありがとう。(고마워요) · `glad` うれしいです。(기뻐요) · `comeback` また{来|き}ますね。(또 올게요)
  - `try` がんばります。(열심히 할게요) · `youtoo` トモもね。(토모도요) · `todaytoo` {今日|きょう}もありがとう。(오늘도 고마워요)
- `loadReply(letterSeq)` → Supabase에서 본인 답장 1행(없으면 null). `saveReply(letterSeq, phraseKeys, bodyKo)` → upsert.
  🔴 db 직접접속 아님 — 앱 supabase 클라이언트(anon 키 + 세션)로. 로그인 세션 있어야 RLS 통과.

### `LetterScreen` (편지 상세) — 답장 영역 추가
- 편지 본문 아래 「답장」 섹션:
  - **로그인 + 답장 있음**: 저장된 내 답장(문구들 후리가나 렌더 + 있으면 한국어) + 「답장 수정」.
  - **로그인 + 답장 없음**: 「답장하기」 → 작성 컴포저(인라인).
  - **게스트**: 「로그인하면 답장을 남길 수 있어요」 담담한 안내(→ MY). 재촉·빨간점 없음.
- **컴포저(가이드)**: 문구 카드 목록(탭해서 선택/해제, 후리가나·해석 표시) → 선택분 미리보기 → (선택)
  한국어 한 줄 입력 → 「보내기」. 보내면 `saveReply` → 토모 짧은 확인 + 저장된 답장 표시.
- 🔴 밝기 헤일로·폭죽 없음. 확인은 담담한 문구 + 토모 read.

### `LetterBoxScreen` (편지함) — 답장 표시(선택)
- 답장한 편지 항목에 작은 「답장함」 표시. (로드 비용: 로그인 시 답장 seq 목록 1쿼리. v1 미표시도 허용 — 상세에서 확인.)

## 무엇이 로그인 전제인가
- 편지 열람·읽기(후리가나·해석) = 게스트도 가능(편지는 현재 데모). **답장 작성·저장 = 로그인 필요**(사용자 데이터).

## 범위 밖 (후속)
- 실 편지 생성(학습 데이터→문안)·도착 실 트리거 — 별도(인증 후 유저데이터 배선 단계).
- 토모가 답장에 **진짜 응답**(자유 생성) — LLM·비용·목소리 일관성·모더레이션 이슈로 큰 스코프. v1은 담담한 확인만.
- 자유 일본어 작문(문구 카드 외) · 답장 여러 통(스레드) · 편지함 답장 뱃지 정교화.

## 검증
- BE: 마이그레이션 적용 + `pg_trigger`/advisor 확인. RLS: 본인 답장만 read/write(anon은 0).
- FE: 빌드0 + @5599. **대표님 로그인 상태**에서 편지 열기→답장하기→문구 선택→보내기→저장·표시→
  새로고침해도 남음(실저장 확인) + Supabase MCP로 `letter_replies` 행 확인. 게스트는 로그인 안내. 라이트/다크·콘솔0.
