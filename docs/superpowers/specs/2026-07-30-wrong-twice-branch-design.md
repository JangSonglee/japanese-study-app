# 2회 연속 오답 분기 — 설계 (독해·청해 객관식)

- 날짜: 2026-07-30
- 대상 화면: `개발/프론트엔드_무스부/tomori-app/src/screens/QuizScreen.jsx` (독해·청해 공용)
- 확정 설계 출처: `기획/JLPT_플로우_검토.md` §③ 오답 처리(71–74행) · §⑥ 17번 피드백(193–199행)
- 선행 기능: 「모르겠어요」 스킵(`2026-07-30-moreugesseoyo-skip-design.md`) — `reaction='unknown'` 이미 존재

## 1. 목적 / 문제

기획 문서의 확정 흐름은 **오답 재노출 + 2회 연속 오답 시 계속/넘어가기 선택**이다
(강제 반복 없음 — PRD 1.3 「학습 의지를 막지 않는다」). 그러나 현재 QuizScreen은
한 번 제출하면 결과 → 다음으로 끝이고 **재노출·재도전이 전혀 없다.**

이 스펙은 QuizScreen에 **2라운드 구조**(1차 전체 → 2차 오답 재노출)와
**2연속 오답 분기 UI**([다시 풀기]/[넘어가기])를 더한다.

## 2. 범위 (대표님 결정 2026-07-30)

| 결정 | 값 | 이유 |
|---|---|---|
| 구현 범위 | **재도전 + 2연속 분기 UI만** | 오답노트 자동저장은 사용자 데이터 → Google OAuth 인증 전제. 인증은 대표님 GCP 키 대기 중이라 이번 범위 밖. 세션 로컬 UI는 지금 완결 가능 |
| 재노출 방식 | **라운드형** (1차 다 풀고 오답만 2차) | JLPT_플로우_검토.md 확정안. 문항 즉시 재시도보다 "오답만 모아 다시"가 문서 원칙과 일치 |
| 요약 성적 | **첫 시도(1차) 정답 수 기준** | 2차 재도전 정답은 학습 보강일 뿐 — 정직한 자가진단. DoneView `total`은 원본 문항 수 유지 |
| 오답노트 | **UI 안내 문구 + TODO 훅만** | 실 저장은 인증 후 배선. 「오답노트에 담았어요」·「넘어가도 오답노트에 남아요」 안내만 |

## 3. 동작 흐름

```
[1차 라운드] 원본 cards 전체를 순서대로 풀이
  · 정답  → 토모 축하  → 결과(해설) → [계속하기]        (correct++)
  · 오답  → 토모 위로  → 결과(해설) → [계속하기]        → 재도전 큐(wrong)에 담김
  · 모름  → 토모 격려  → 결과(해설) → [계속하기]        → 재도전 큐(wrong)에 담김
        ↓ 1차 끝(idx가 끝에 도달)
  wrong 비었으면 → 요약(DoneView)
  wrong 있으면   → 2차 진입: roundCards=wrong, round=2, idx=0, wrong=[]

[2차 라운드] 1차에 못 맞춘 문제만 재노출 (= 이미 한 번 틀림)
  · 정답      → 결과(해설) → [계속하기]
  · 오답/모름  = 2연속 → 결과(해설) + [다시 풀기] [넘어가기]
        · [다시 풀기] → 같은 문제 재도전(selected·reaction 초기화, idx 유지)
        · [넘어가기]  → 「넘어가도 오답노트에 남아요」 안내 → 다음
        ↓ 2차 끝 → 요약 (3차 없음 — 강제 반복 금지)
```

- **2연속 성립 조건**: 2차 재노출 문제는 이미 1차에서 틀림 → 2차에서 또 못 맞추면 곧 2연속.
  즉 `round === 2 && (오답 || 모름)` 이면 분기 UI.
- **2차에서도 「모르겠어요」 버튼 유지**: 누르면 2연속 취급(오답과 동일 분기). 별도 예외 없음.
- 문서 §⑥-3의 `[1회 오답] … [계속하기]` / `[2회 연속] … [다시 풀기][넘어가기]` 상태 2종을 그대로 구현.

## 4. 상태 모델 (QuizScreen)

기존 상태에 더한다. props `cards`(원본)는 불변 유지 — DoneView `total` 산정용.

- `round`: `1 | 2` — 현재 라운드.
- `roundCards`: 현재 라운드가 푸는 카드 배열. 초기 = props `cards`. 2차 진입 시 = 1차 wrong.
- `wrong`: 1차에서 못 맞춘 카드 누적(오답 + 모름). 2차 진입 시 소비 후 비움. **2차에선 누적하지 않음**.
- `reaction`: `null | 'correct' | 'wrong' | 'unknown'` — 모달 표시(풀이 phase) + **결과 화면 버튼 판정** 공용.
  기존엔 `toResult`에서 null로 껐으나, 이제 결과 화면까지 유지하고 `next`/`retry`에서 null.
  모달 표시 조건을 `reaction && phase === 'solve'`로 좁힌다.
- `correct`: 첫 시도(round 1) 정답 수. **round 1에서만** 증가.
- `idx`: 현재 roundCards 내 인덱스(기존과 동일 의미, 대상만 roundCards).

`done` = round 2에서 `idx >= roundCards.length` (또는 1차 종료 시 wrong이 비어 바로 요약).

## 5. 흐름 함수 (설계 수준)

- `submit()`: 정답이면 `round === 1 && correct++`, `reaction='correct'`.
  오답이면 `reaction='wrong'`, `round === 1 && wrong.push(card)`.
- `skip()`: `reaction='unknown'`, `round === 1 && wrong.push(card)`.
- `toResult()`: `phase='result'` (reaction 유지 → 모달만 닫힘).
- `advance()`: 다음 문제. round 1에서 마지막이면 wrong 유무로 2차 진입 or 요약. round 2에서 마지막이면 요약.
  공통: `idx++`, `phase='solve'`, `selected=null`, `reaction=null`, 토글(furi/trans)·wordSheet 초기화.
- `retry()`: 같은 문제 재도전 — `phase='solve'`, `selected=null`, `reaction=null`. `idx` 유지.

**결과 화면 버튼 규칙**:
- `round === 1` → 「계속하기」 → `advance()`
- `round === 2 && reaction === 'correct'` → 「계속하기」 → `advance()`
- `round === 2 && reaction !== 'correct'`(2연속) → 「다시 풀기」(`retry`) + 「넘어가기」(`advance`) 2버튼,
  「넘어가도 오답노트에 남아요」 안내.

## 6. 안 건드리는 것 (YAGNI)

- **BE/DB/오답노트 화면(18·47번)/인증**: 무관. 오답노트 실 저장은 인증 후 별도.
- **DoneView 내부**: `known=correct`(첫 시도), `total=cards.length`(원본) 그대로 넘기면 되므로 컴포넌트 변경 없음.
- **정오 판정 없는 유형**: 우리 QuizScreen은 전부 객관식(정오 판정 있음)이라 문서 §⑤-170 「스피킹 미적용」은 해당 없음.
- **밝기(헤일로) 축하**: 「새 쪽지」 전용(PRD 14.2.1) — 기존대로 문구·색만.

## 7. 검증 방법

FE 빌드(`npm run build`) → 포트 5599 프리뷰:
- 1차에서 일부 오답 → 「계속하기」로 진행 → 1차 끝나면 **오답만 2차 재노출**.
- 2차 오답 → 결과에 **[다시 풀기]/[넘어가기]** + 오답노트 안내 노출.
  - [다시 풀기] → 같은 문제 재도전. [넘어가기] → 다음.
- 2차에서 정답 → 「계속하기」로 진행.
- 1차 전부 정답 → 2차 없이 바로 요약.
- 「모르겠어요」도 1차 재도전 큐에 포함되고, 2차에서 누르면 2연속 분기.
- 요약(DoneView) 정답 수 = **첫 시도 기준**(2차 정답은 미반영), total = 원본 문항 수.
- 정답/오답/모름 기존 모달 회귀 정상, 콘솔 에러 0.

구현·검증 후 `기획/진행상태.md`에 결정·근거 기록.
