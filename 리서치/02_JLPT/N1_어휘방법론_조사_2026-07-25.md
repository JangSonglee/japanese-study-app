## ① 문제 정의 요약

기존 N5~N2 선정 = **①JF Can-do(범위) + ②공개 코퍼스 빈도 wordfreq(순위) + ③Tanos 교차검증**.
N1(C1 상당)에서 두 축이 동시에 무너진다.

| 축 | N2까지 | N1에서 |
|---|---|---|
| ① JF Can-do | B1(N3)·B2(N2)까지 공개 | 🔴 **C1(≈N1) 범위는 JF 표준에 없다.** 범위를 자를 자가 사라짐 |
| ② wordfreq 빈도 | 범위 안 순위 매김에 유효 | 🔴 **정의상 드문 말**이라 일반 빈도 순위가 신호가 못 됨 (논설·학술·법률·문학어는 일반 빈도 낮음) |

**슈슈 가설(=검증 대상)**: 「분야축」 — 일반 빈도는 낮아도 **특정 장르(논설·학술·법률·경제·문학 등)에 편중 출현**하는 어휘가 N1 영역이다. 단순 빈도 대신 **장르별 빈도 분포의 편중도(genre-skew)**로 잡는다.
→ 이 방법이 성립하려면 **「장르가 태그된, 상업 이용 안전한 코퍼스」**가 있어야 한다. 그게 이 조사의 핵심 질문이다.

## ③ 분야축 방법 — go / 조건부 / no-go 결론

### 판정: **조건부 GO (사실상 GO)**

- ✅ **방법의 신호는 실재한다** — PoC에서 N1 형식·학술어와 일상어의 편중도가 **+1.53만큼 분리**되었다(⑥).
- ✅ **상업 안전한 장르 코퍼스를 직접 구축할 수 있다** — 문학(青空文庫 PD) / 논설·행정(国会会議録·白書, CC BY 호환) / 법률(e-Gov 法令, 著13조) / 학술 proxy(Wikipedia CC BY-SA) / baseline(wordfreq). **BCCWJ를 안 밟고 전 장르 축을 세울 수 있다.**
- ⚠️ **조건 두 가지**:
  1. **BCCWJ의 pre-computed 장르 신호(教科特徴語·레지스터별)는 상업 회색지대라 못 쓴다.** → 우리가 원천 텍스트에서 **직접 코퍼스를 만들고 skew를 계산**해야 한다(N2까지와 다른 규모의 공수).
  2. **학술 register가 가장 약한 다리.** 진짜 논문 코퍼스(J-STAGE)는 라이선스 불명이라 배제 → **Wikipedia+白書 proxy로 대체.** 순학술어 일부는 놓칠 수 있음.

> 🔴 **no-go가 아닌 이유**: N3에서 BCCWJ가 막혔을 때 wordfreq로 갈아탔듯, 여기서도 **막힌 원천(BCCWJ) → 상업안전 대체 원천(자체 구축)**의 같은 패턴이 성립한다. 다른 점은 대체물이 「이미 만들어진 표」가 아니라 「우리가 돌려야 하는 파이프라인」이라는 것뿐이다.

## ④ 권장 파이프라인 (기존 3단 구조 유지: 범위 → 순위 → 검증)

| 단 | N2까지 | **N1 대체** |
|---|---|---|
| **①범위(scope)** | JF Can-do B1/B2 | 🔴 **Tanos N1 목록(CC BY) 3,117건** − 기존 1,600 중복 제거. + **jlpt.jp N1 능력기술(C1)**로 주제 최소범위 보정. Can-do가 없으니 Tanos N1이 그 자리를 대신한다 |
| **②순위(rank)** | wordfreq 일반 빈도 | 🔴 **장르 편중도(genre-skew) 점수.** 각 후보어를 5개 장르 코퍼스(문학·논설·행정·법률·학술proxy)에서 형태소분석·표제형 합산 → `skew = 장르별 상대빈도의 max(또는 분산/엔트로피)`. **일반 빈도로 죽는 어휘를 특정 장르에서 살린다** |
| **③검증(verify)** | Tanos 급수 교차 + 사람 | (a) **Tanos N1 태그** 기계 기록(§9.4식) (b) **jlpt.jp 샘플 프로파일** 대조 (c) **사람 최종 감수** (d) **기존 1,600 중복 0** 검사 |

**②의 구체 지표(PoC 검증형)**: `norm_skew(w) = log10(genre_pm / general_pm) − 코퍼스_size_offset`
- `general_pm` = wordfreq per-million(baseline). `genre_pm` = 해당 장르 코퍼스 per-million.
- `size_offset` = 일상어 다수에 대한 median(log10 genre/general) — **소형 코퍼스의 크기 팽창을 상쇄**(PoC에서 −0.50).
- 여러 장르 중 **최댓값 skew**가 큰 어휘 = 그 장르의 특징어 = N1 후보. **일반 빈도(zipf)는 무시하고 편중도만 본다.**

> **각 원천은 `source`가 아니라 `note`에 적는다**(§1.2-1 원칙 연장). `source`는 `ref_only:tanos_n1+genre_skew` 한 값으로 고정, 행마다 다른 것(어느 장르에서 튀었는지·Tanos 태그)은 `note`.

## ⑤ 플랜 B (코퍼스 구축 공수가 과하거나 대표님이 축소를 원하면)

**N2 방법을 최대한 재활용하되 ①축만 Tanos N1로 갈아끼운다.**

| 단 | 플랜 B |
|---|---|
| ①범위 | Tanos N1(CC BY, scope) − 기존 1,600 중복 제거 |
| ②순위 | **wordfreq 일반 빈도**로 "N1 목록 **안에서** 상대적으로 흔한 것부터". N1끼리 비교라 저빈도 절대값이 문제 안 됨 |
| 분야 태깅 | **수동 분야 태그**(논설/학술/법률/문학/일반) — 코퍼스 구축 없이 사람이 감으로 부여 |
| ③검증 | jlpt.jp 샘플 프로파일 + Tanos 태그 + 사람 |

- 장점: **코퍼스 구축 0.** N2 파이프라인 거의 그대로. 착수 즉시 가능.
- 단점: 분야축의 **정량 신호가 없다**(수동 태깅은 재현·검증 불가). "왜 이 단어가 N1인가"의 근거가 Tanos 목록 소속 + 사람 판단뿐 → 우리가 N3~N2에서 쌓아온 **"기계가 신호를 주고 사람은 예외만"** 원칙에서 후퇴.
- **권장**: 시간이 되면 ④(정식), 압박되면 ⑤로 시작해 ②축(장르 코퍼스)을 나중에 얹기. **scope·중복검사·검증은 두 안이 동일**하므로 나중 전환 비용이 낮다.

## ⑥ PoC 결과 — 「신호가 실재하는가」 눈으로 확인

**설정**: 학술·논설 성격의 日본어 Wikipedia 16문서(CC BY-SA)를 형태소분석(fugashi) → 표제형 합산 코퍼스(내용어 78,391토큰). 각 어휘의 `norm_skew`를 wordfreq 일반빈도 대비로 계산, 일상어 24개로 크기 오프셋(−0.50) 보정.

| 그룹 | 평균 norm_skew | 판정 |
|---|---|---|
| **N1 형식·학술 후보** 21개(考察·仮説·概念·要因·抑制·規範·普遍·前提·抽象·定義…) | **+1.59** (median +1.60) | 전부 강한 양(+) |
| **일상어 통제군** 17개(見る·人·今日·食べる·時間·子供·車…) | **+0.06** (median −0.04) | 0 근처, 예상대로 |
| **분리 폭** | **+1.53** | 🟢 **명확한 신호** |

**대표 값**: 普遍 +2.30 · 規範 +2.23 · 概念 +1.92 · 仮説 +1.88 · 抑制 +1.86 · 要因 +1.85 (일반빈도 zipf는 3.7~4.4로 낮은데 편중도로 뚜렷이 부상).

🔴 **결정적 부수 발견**: 후보 중 **顕著·遵守·譲歩 3개가 이 코퍼스에 아예 없었다.** 셋 다 **법률·교섭 register**라 Wikipedia(백과·학술)엔 안 나온다. → **단일 장르로는 N1 어휘를 다 못 잡는다**는 것을 실측이 증명. **④의 「다장르 코퍼스」 설계가 필수임을 PoC가 스스로 보여줬다**(遵守·譲歩는 e-Gov 法令·国会会議録에서 잡힌다).

> ⚠️ 노이즈도 정직하게: 통제군 중 言う(+1.65)·大きい(+1.47)가 높게 나왔다 — 소형 코퍼스에서 Wikipedia 특유의 「〜という」 남용 등 때문. **정식 파이프라인은 코퍼스를 키우고(장르당 수십만+ 토큰) 다장르 max를 쓰면 이 노이즈가 줄어든다.** PoC는 "신호 존재"의 증명이지 최종 지표가 아니다.
> 스크립트: 스크래치패드 `poc_genreskew.py`·`compute.py`(재현용, 저장소엔 미커밋).
