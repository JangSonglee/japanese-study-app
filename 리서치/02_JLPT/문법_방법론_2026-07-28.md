# JLPT 문법 — 수집·제작 방법론 (v1.0)

> 작성 2026-07-28 · 담당 슈슈(리서치) · 브레인스토밍 승인(대표님) 후 스펙화
> 상위 맥락: `기획/진행상태.md`(2-c 병렬 트랙) · 규격 `리서치/콘텐츠_입력규격.md` 4.2 · 출처 `리서치/02_JLPT/자료수집.md`
> 짝 선례: 단어 방법론(`N1_어휘방법론_조사_2026-07-25.md` 등) — 이 문서는 그 3단 구조를 **문법에 맞게 변형**한 것

## 0. 이 문서가 하는 일
문법 콘텐츠(`grammar_items`)를 **무엇을 골라(범위) 어떻게 채우는지(작성)** 정한다.
FE 본편의 JLPT 허브에 "문법" 영역을 켜려면 이 방법론으로 급수별 문형을 채워야 한다(단어가 먼저 깔린 것처럼, 문법은 독해·청해 지문의 재료가 된다).

## 1. 🔴 단어와 결정적 차이 — 순위(빈도)가 없다
단어는 "N3에 **어떤 단어**를 고를까"가 열려 있어 ①범위(JF Can-do) ②코퍼스 빈도 순위 ③교차검증의 3단이 필요했다.
문법은 다르다 — **급수별 문형 목록이 거의 정형**이다("N3 문법이 무엇인가"는 출판사·리스트 간 편집 여지가 작다). 그래서:
- **코퍼스 빈도 순위 단계가 없다.** 급수의 **표준 세트를 통째로** 취한다.
- 대신 "정형인 목록을 어디서 가져오나(범위)"와 "예문·해설을 어떻게 자작하나(작성)"가 본체다.

## 2. 방법론 3단 (문법 변형)

### ① 범위 — Tanos 급수별 문법 리스트(CC BY)를 골격 (대표님 결정 2026-07-28)
- 급수별 Tanos 문법 리스트(tanos.co.uk/jlpt, CC BY)를 **표준 세트의 골격**으로 삼는다.
- 🔴 근거: 문형 목록은 정형(사실에 가까움)이라 Tanos를 scope 백본으로 써도 저작권 리스크가 낮다 — **N1 단어에서 Tanos를 scope 백본으로 쓴 것과 같은 논리**(편집저작물성이 약한 정형 목록). 뜻·접속·예문은 전량 자작이라 "목록을 옮긴 앱"이 되지 않는다.
- ⚠️ Tanos는 **구 시험 기준**이라 신 시험과 소폭 불일치 가능(자료수집.md). → 아래 교차검증으로 보정.

### ② 선정 — 급수 표준 세트 전량 (대표님 결정 2026-07-28)
- 급수별 표준 문형을 **빠짐없이** 채운다(핵심 우선 배치 아님). 문법은 유한해서 가능(급수별 대략 규모는 6장).
- 정렬 = **교육 순서**(기능·난이도 그룹). 코퍼스 순위를 쓰지 않으므로 정렬은 "가르치는 순서"로 준다(교재가 담는 그 순서의 성격).

### ③ 교차검증 — 공식 샘플 + 2차 리스트 + 팀
- **공식 샘플 유형**(jlpt.jp) 및 **2차 공개 리스트**(JLPT Sensei 등 비공식)와 대조해 Tanos 세트의 누락·구판 잔재를 보정.
- 판정은 **기계가 `note`에 찍는다**(단어의 Tanos 교차판정과 동일 원칙 — 사람이 손으로 적으면 그 문장이 또 검수 대상). `note` 예: `Tanos:N3 · 공식샘플 유형O · 2차리스트 일치`.
- `verify=team`으로 출시(단어와 동일 — 공개 리스트 대조가 가능). `native`는 출시 후 순차.

## 3. 🔴 저작권 (규격 1장 준수)
| 자리 | 값/원칙 |
|---|---|
| **문형 목록(범위)** | Tanos(CC BY) 골격 — 정형이라 리스크 낮음. **`source`가 아니라 `note`에** 표기(규격 1.2-1: 적는 자리가 뜻을 바꾼다) |
| **접속·뜻·용법·예문** | **전량 자작** → `source=own` |
| 공식 샘플 | **유형만** 참고, 원문 복제 금지(`ref_only:jlpt_official`은 유형 참고 시) |
| 금지 | 시중 교재·학원 자료의 문형 배열·예문·해설 복제 |

> `source` 후보: **`ref_only:tanos_grammar+official_sample`**(N3 단어가 `ref_only:jfs_cando_b1+corpus_freq`였던 것과 같은 꼴 — "방법론이 출처"). 행별 상세(어느 Tanos 급수·공식 유형 여부)는 `note`.

## 4. 작성 규격 (`grammar_items` CSV — 규격 4.2, 15열)
```
content_key,level_code,pattern,pattern_ruby,romaji_ko,connection,meaning_ko,usage_note,
example_ja,example_ko,example_ruby,politeness,source,verify,note
```
| 컬럼 | 규칙 |
|---|---|
| `content_key` | `jlpt.n5.grammar.0001` … (규격 4.0 자연키) |
| `pattern` / `pattern_ruby` | 문형 표기 + 브래킷 루비(규격 3.1). 한자 없으면 동일 |
| `romaji_ko` | pattern_ruby·example_ruby에서 **기계 생성**(단어와 동일 `kana_to_ko`, 규격 3.2). 손으로 안 적는다 |
| `connection` | 🔴 접속형(예: `동사 た형 + ばかり`). 문법 카드의 절반이 이 정보(규격 4.2) |
| `meaning_ko` / `usage_note` | 뜻 / 뉘앙스·주의 — 자작 |
| `example_ja` / `example_ko` / `example_ruby` | 예문(브래킷 루비) / 해석 / — 자작 |
| `politeness` | `casual`/`polite`/`humble`/`honorific`/`-` |

### 4.1 🔴 예문은 "그 급수 이하 어휘"로 쓴다
- 예문은 **해당 급수 이하의 단어**(이미 뽑은 vocab 세트)로 구성함을 원칙으로 한다.
- 이유: ① 학습자가 예문을 읽을 수 있어야 한다(모르는 상위 단어가 섞이면 문법이 아니라 단어에서 막힌다) ② 나중에 **독해·청해 지문의 재료 제약과 일관**(그 급수의 단어+문법으로만 짓는다).
- 불가피하게 상위 단어가 필요하면 후리가나+예문 해석으로 보조(강제 규칙 아닌 품질 기준). 검수 시 예문 형태소를 vocab 세트와 대조해 **초과 어휘를 후보로 보고**(기계가 좁히고 사람이 판정 — 단어 3.2.5-2와 같은 방식).

## 5. 실행 파이프라인 (단어 파이프라인 재사용)
1. **Tanos 문법 리스트 파싱** → 급수별 표준 세트 확정(참조본 도구화, `tanos_ref_n3.py` 패턴 재사용).
2. **교차검증**: 공식 샘플 유형·2차 리스트 대조 → 누락 보정 + `note` 자동 태깅.
3. **배치 작성**(슈슈, 급수별): 접속·뜻·용법·예문 자작. N5부터.
4. **기계 검수**(`build_grammar.py` 신설, `build_n2.py`의 QA 기계 재사용): 루비 검증·한글발음 기계생성 대조·중복·급수 분리·**예문 어휘 급수 초과 후보**.
5. **대표님 QA**(예문 자연스러움·뜻 정확도 — 기계가 못 잡는 것).
6. **DB 임포트 + 공개**(단어와 동일: `content_key` UPSERT, `is_published` 플립) → FE 허브 문법 영역 켜기.

| 급수 | 표준 문형(대략) |
|---|---|
| N5 | ~80 |
| N4 | ~100 |
| N3 | ~150 |
| N2 | ~180 |

## 7. 검증 체크리스트 (기계)
- 루비 브래킷: `{}` 벗김 == pattern / example_ja, 읽기 이어붙임 == reading (규격 3.1)
- 한글 발음: `kana_to_ko(ruby)` == romaji_ko (불일치 0)
- 중복: content_key 유일 · 동일 급수 내 pattern 중복 0 · 급수 간 문형 중복은 의도(상위서 심화) 시 note 명시
- 급수 분리: 예문 형태소 vs 해당 급수 이하 vocab 세트 → 초과 어휘 후보 리스트(사람 판정)
- 접속형(`connection`) 필수 채움 확인

## 8. 순서·범위
- **N5 → N4 → N3 → N2 → N1**(사용자가 만나는 순서, 단어와 동일).
- 이 문서는 **문법 한 영역**의 방법론이다. 독해·청해는 별도 스펙(문법이 재료로 깔린 뒤 착수).

## 9. 미해결 / 확인 필요
- Tanos 문법 리스트의 신 시험 불일치 폭 — 1단계 파싱+교차검증에서 실측 후 보고.
- 예문 어휘 급수 제약을 "강제"로 할지 "권장"으로 할지 — 현재 **권장 + 초과 후보 보고**(강제하면 초기 문형 예문이 부자연스러워질 수 있음). 대표님 확인 가능.
- `politeness`·`connection`의 팀 검증 기준(경어 문형은 실례 리스크) — native 전까지 team 대조로.
