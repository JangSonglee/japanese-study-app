# N1 단어 배치 작성 브리프 (슈슈용)

> 이 문서는 N1 단어 400건의 예문·뜻을 배치로 작성할 때 **매 배치 서브에이전트가 먼저 읽는 사양**이다.
> 작성 결과는 `n1_data{1..4}.py`의 `ROWS{1..4}` 리스트이고, `build_n1.py`가 이를 17열 CSV로 조립·검수한다.
> 기준: N2의 `build_n2.py`·`n2_data*.py`와 **동일 포맷**. 다른 것은 선정축(장르 편중도)뿐이며 그건 build_n1이 자동으로 채운다.

## 1. 행(ROW) 형식 — 정확히 8필드 튜플

```python
(ruby, pos, conj_type, transitivity, meaning_ko, meaning_ko_alt, example_ja, example_ko)
```

작성자는 이 8개만 쓴다. **headword·reading·romaji_ko(한글발음)·content_key·audio·source·verify·note·장르·편중도·Tanos는 build_n1.py가 기계로 채운다.** 사람이 headword를 또 적으면 흔들리므로 절대 중복 기재하지 않는다.

## 2. 루비(후리가나) 표기 — `{표기|읽기}` 브래킷

- **한자 1글자당 읽기 1개**를 `|`로 구분: `{老後|ろう|ご}`(老=ろう, 後=ご), `{批評|ひ|ひょう}`(批=ひ, 評=ひょう).
- 또는 **묶음 읽기 1개**도 허용: `{発表|はっぴょう}` 처럼 읽기를 하나만 두면 표기 전체에 대응. (build QA 규칙: 읽기 개수 = 1 **또는** 한자 글자수와 정확히 일치.)
- **한자에만 루비**를 단다. 가나(ひらがな·カタカナ)는 브래킷 없이 그대로: `{生活|せい|かつ}について`.
- 오쿠리가나는 브래킷 밖: `{顧|かえり}みる`, `{帯|お}びる`, `{取|と}り{組|く}む`.
- 🔴 **예문(example_ja)의 모든 한자에도 반드시 루비**를 단다. 루비 없는 한자가 남으면 `[예문루비누락]` 오류가 난다.
- 🔴 한글 발음은 `ruby`에서 규칙(kana_to_ko.py)으로 **기계 생성**된다. 촉음·발음(ん)은 다음 루비 첫 글자를 보고 결정되므로, 루비 경계를 정확히 끊어야 한다. 확신 없으면 글자 단위로 끊어라(`{発|はっ}{表|ぴょう}`보다 `{発表|はっぴょう}` 같은 묶음이 안전할 때가 있음 — 단 묶음은 형태소 경계 정보를 잃으니 한자 2자 숙어는 글자별 권장).

## 3. 필드 규격

| 필드 | 값 |
|---|---|
| `pos` | `noun`/`verb`/`i_adj`/`na_adj`/`adv`/`conj`/`pron`/`counter`/`prefix`/`suffix`/`interj`/`expr` 중 하나 |
| `conj_type` | 동사: `g1`(5단)/`g2`(1단)/`g3_suru`/`g3_kuru`, する명사: `suru_noun`, 형용사: `i_adj`/`na_adj`, 그 외: `-` |
| `transitivity` | 동사만: `vi`(자동)/`vt`(타동)/`vi_vt`(양용). 그 외: `-` |
| `meaning_ko` | 핵심 뜻(간결하게, 한국어). |
| `meaning_ko_alt` | 보조 뜻/뉘앙스. 없으면 `-`. |
| `example_ja` | N1 수준의 **자연스러운** 예문(루비 포함). 그 단어의 대표 용법을 보여줄 것. |
| `example_ko` | 예문의 한국어 번역(자연스러운 해요체/합니다체). |

🔴 **동사면 conj_type·transitivity를 `-`로 두면 오류**. 반드시 채운다.

## 4. 절대 금지 (CSV 파손·QA 실패)

- 어떤 필드에도 **쉼표(`,`)·줄바꿈** 금지 (CSV가 쉼표 구분). 일본어 예문에 읽기 쉼표가 필요하면 `、`(전각) 사용.
- 빈 필드 금지(뜻이 없으면 `-`).
- **기존 N5·N4·N3·N2·파일럿에 이미 있는 단어 금지** — N1은 상위 급수라 중복이면 안 된다. (build_n1이 5파일 대조로 잡지만, 애초에 넣지 말 것.)
- headword는 배정된 목록 그대로. 임의 교체·추가 금지.

## 5. 예문 품질 기준 (대표님 QA 통과 목표)

- 그 단어의 **가장 전형적인 문맥**을 담을 것(사전 예문처럼). N1은 격식·논설·문어가 많으므로 신문·설명문·비즈니스 톤이 자연스럽다.
- 한 문장, 20~35자 내외. 너무 길게 만들지 말 것(루비 실수↑).
- 학습자가 **뜻을 유추할 수 있는** 문맥. 동어반복(단어를 그냥 정의로 되풀이) 금지.
- 정치·종교·논쟁적 소재는 중립적으로. 특정 실존 인물·사건 단정 금지(뉴스 오해 방지 원칙).


## 7. 검수 (작성 후 build_n1으로 자동)

`python 도구/build_n1.py` → `검수 오류 0건`이어야 한다. 오류 유형: 읽기 가나검증·루비수·루비대상·예문루비(누락/수)·발음변환·중복·pos/conj/tr·동사필수·빈칸·CSV파손·기존5파일중복. 오류가 나면 해당 행을 고쳐 0으로 만든다.
