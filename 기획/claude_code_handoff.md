1. `PRD.md`와 `project_master.md`를 먼저 읽고 전체 맥락(철학, 5개 코스, 수익모델, 학습 루프, 카메라 번역, 단어장 태그 구조)을 파악할 것
2. 아래 "전체 화면 목록"을 기준으로 **Lo-fi 와이어프레임**을 제작할 것
   - 그레이스케일(회색조)만 사용, 브랜드 컬러·실제 카피 문구는 넣지 않음 (레이아웃과 정보 위계에만 집중)

   - 실제 문구·색상·캐릭터 일러스트는 이후 Hi-fi 단계에서 반영 예정이므로 지금은 배제
3. 화면 간 이동 흐름은 이미 확정되어 있으므로(아래 "참조할 기존 플로우" 참고) 임의로 새 흐름을 만들지 말고 그대로 따를 것
4. 화면 목록에 없는 새로운 화면이 필요하다고 판단되면, 추가하기 전에 먼저 알려줄 것 (임의 추가 금지)

## 참조할 기존 플로우 (이미 확정됨, PRD 참고)

- **온보딩 플로우**: 스플래시 → 앱 소개 → 회원가입 → 진단 테스트(4문항) → 추천 결과 → 레벨 테스트 → 첫 학습 시작
- **학습 루프**: 오늘의 학습 시작 → 레슨 콘텐츠 학습 → 퀴즈 진행 → 정답/오답 분기(오답 시 오답노트 자동저장) → 우표 적립 → 오늘의 학습 요약 → 다음 레슨 또는 홈으로
- **구독 전환**: 가입 완료 → 7일 프리미엄 체험 → D6 알림 배너 → 플랜 선택 화면 → 구독 결제 진행 / 무료로 계속 → (무료 유지 시 설정에서 언제든 구독 전환 가능)
- **카메라 번역**: 번역 탭 진입 → 카메라 촬영 → OCR·번역 처리 → 인식 결과 화면 → (학습 연계 알림 / 번역 결과만 표시) → 단어 탭 → 저장 위치 선택(태그 지정) → 계속 촬영 / 단어장으로 이동

### 상태 변형 추가 (4) · 2026-07-22 — 새 번호 부여하지 않음
> 기존 화면의 상태 변형이므로 8·12·14·16·17과 동일하게 **같은 번호 아래 프레임만 추가**.

- **11 — 여행회화 변형**: 급수 셀렉트 자리에 **상황 8카테고리**(여행 동선 순서) + `TIP만 보기` 필터 + 표현 수집형 진행률
- **11 — 읽기형 목록 변형**: 프로그레스바 대신 **"N회 읽음 · 최근 읽은 날짜"**. 뉴스=최근 기사+읽은 기사 필터 / 전래동화=전체 목록
  - ⚠️ 위 둘은 11번 memo에 *"타 코스 변형"* 이라고 **글로만 적혀 있었고 프레임이 없었다**
  - 비즈니스 변형은 프레임 없음 — JLPT 허브에서 **축 이름만 교체**(명시적 재사용)
- **19 — 오프라인 우표(도착 예정)**: 받은 우표=채운 사각 / 도착 예정=**점선 사각**. 하단에 "학습 기록은 이미 저장됨" 상시 표시
- **28 — 오프라인 촬영 대기열**: 버튼 문구가 "촬영하기"가 아니라 **"찍어두기"**(지금 결과가 안 나온다는 걸 버튼이 말해야 함). 온라인 복귀 시 **조용히 자동 처리**

**총 52개 화면/상태** (기존 44 + 추가 승인 8. 프레임 69장. 16번 퀴즈는 서브 유형 6종. 공통 컴포넌트인 "단어 탭 팝업"은 여러 화면에서 재사용되므로 별도 카운트하지 않고 1개로 처리)

## Claude Code 작업 시 유의사항

- 이 프로젝트는 아직 코드베이스가 없는 순수 기획·디자인 단계입니다. Lo-fi 와이어프레임은 실제 프로덕션 코드가 아니라 레이아웃 검토용 산출물입니다.
- 와이어프레임을 코드로 표현할 경우(HTML/React 등), 실제 앱 개발 스택과 무관하게 "검토용 정적 화면"으로 취급하고, 44개 화면을 빠짐없이 순서대로 제작할 것
- 화면 하나당 최소 정보: 상단 영역(헤더/뒤로가기), 본문 레이아웃 블록, 하단 액션(버튼/탭바) 여부
- 진행 순서: A → B → C → D → E → F → G → H 그룹 순서대로 제작 권장 (사용자 여정 순서와 동일)
