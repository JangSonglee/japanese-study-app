문서를 다시 읽을 때 **"왜 이렇게 했지?"** 가 나올 만한 것들입니다.

| 결정 | 이유 |
|---|---|
| **쿠키 → 우표·편지** | *"쿠키 7개 → PDF"* 의 논리를 설명할 수 없었다. **우표를 모으면 편지가 온다**는 은유로 연결이 완결됨 |
| **캐릭터 = 등불** | 성장 서사를 기각하면서 "쿠니가 무엇인지" 정체까지 사라졌었다. 등불은 *"밝혀주되 끌지 않는다"* 라 철학과 일치 |
| **급수 잠금 폐기** | 콘텐츠를 잠그는 건 PRD 1.3·12장과 정면 충돌. `추천`/`도전` 라벨로 대체 |
| **읽기형은 진행률 대신 "N회 읽음"** | 뉴스는 콘텐츠가 무한이라 분모가 없다. 읽기는 "끝냈다"가 무의미하고 **깊이**가 중요 |
| **후리가나/발음 토글 분리** | 수명이 다르다 — 후리가나는 N2까지 쓰지만 한글 발음은 빨리 떼야 할 보조바퀴(`つ`·`ざ`를 정확히 못 적음) |
| **해석은 토글이 아니라 문장 탭** | 전체를 켜면 일본어를 건너뛰고 해석만 읽는다. **막힌 문장만** 여는 구조로 의존을 구조적으로 차단 |
| **Pretendard JP 탈락** | 가나만 일본식이고 **한자는 한국식**. 섞이면 틀렸다는 사실 자체가 감춰져 더 위험 |
| **오프라인 3분할** | "오프라인 저장(구독자용)"이 *열람*까지 막는 것처럼 읽혀 모순. ①열람 ②촬영은 무료도, ③미리받기만 구독 |
| **기능 5코스 / 콘텐츠 3코스** | 무거운 건 기능이 아니라 **콘텐츠**. 기능은 5코스가 공유하지만 콘텐츠는 코스마다 따로 만들어야 함 |
| **18번은 Toast가 아니라 Snackbar** | `보기` 액션 버튼이 있다. Toast로 발주하면 터치 안 받는 물건이 나옴 |
| **다크 모달엔 테두리 필수** | 다크 표면은 어떤 딤을 얹어도 배경과 **1.39:1이 한계**. 스크림만으로 분리 불가 |
| **Auth·DB·Storage = Supabase 통일** | Auth와 DB를 다른 벤더로 나누면 `user_id`를 앱이 직접 동기화해야 하고 RLS를 못 쓴다. 1인 개발에선 순수한 손해 |
| **오프라인 학습에도 우표 지급** | 안 주면 구독 혜택(미리 받기)이 반쪽. 조작은 **"판정을 로컬에 맡기지 않는 것"** 으로 푼다 — 원장은 서버 전용 쓰기 |
| **오프라인 우표는 "도착 예정"으로 표시** | 이미 받은 것처럼 보였다가 회수하면 배신감. 처음부터 "예정"이라 말하는 게 유일하게 정직하다. 🔴 **검증 실패해도 학습 기록은 항상 반영**(우표만 보류) |
| **오프라인에서 토모를 어둡게 하지 않는다** | 토모의 밝기는 **학습 상태** 신호다. 통신 상태로 어두워지면 "네 잘못"처럼 읽힌다 — 연결이 끊긴 건 사용자 탓이 아니다 |
| **CJK 폰트는 폭으로 판별하면 안 된다** | CJK 글자는 **어떤 폰트든 정확히 1em**이라 폰트가 달라도 폭이 같다. 폭으로 재면 "렌더링 안 됨"이라는 **거짓 결론**이 나온다 → **픽셀 비교 + 반드시 달라야 하는 대조군**(고딕 vs 명조)으로 측정 유효성부터 확인. 한글은 폭 비교가 유효 |
| **후리가나는 문자열이 아니라 "루비 표기"로 받는다** | `おてつだい` 한 줄로는 **어느 글자에 어떤 루비**인지 알 수 없다. 제작자는 `{手\|て}{伝\|つだ}`로 쓰고 임포터가 좌표 JSON을 만든다. 좌표를 원본으로 두면 사람이 못 고친다 |
| **한글 발음은 사람이 적지 않고 기계가 만든다** | 규칙(규격 3.2)이 결정적이라 `ruby`에서 생성된다. 파일럿 100건 **100/100 일치** 검증 완료. 손으로 적으면 2,250건에서 반드시 흔들린다 |
| **순가나 복합어는 형태소 경계를 표시할 수 없다** | 조각 경계는 **루비 브래킷으로만** 생긴다. 한자가 없는 `そのうえ`(その+うえ)는 경계가 안 보여 **소노「오」에**로 잘못 나왔다(옳음: 소노**우**에). → `WORD_EXCEPTIONS`에 브래킷을 넣어 조각을 강제 분리. 🔴 **자동 판정은 불가능**(형태소 사전 문제) — **기계가 후보를 좁히고 사람이 판정**한다. 1,200건 중 후보 13건·오류 1건 (규격 3.2.5-2) |
| **촉음·발음은 루비 경계를 넘고, 장음은 넘지 않는다** | 변환기 첫 판이 14/100 틀렸고 원인이 전부 이것이었다. `{発\|はっ}{表\|ぴょう}`의 받침은 **다음 루비의 첫 글자**를 봐야 정해진다. 조각별로 돌리면 **조용히 틀린다** |
| **모든 콘텐츠 행에 `source`·`verify`를 필수로 둔다** | 저작권 사고가 나면 **"이 2,250건 중 어느 것을 지워야 하나"** 에 답할 수 있어야 한다. 나중에 채우면 못 채운다 — 며칠 지나면 어디서 봤는지 아무도 기억 못 한다 |
| **콘텐츠에 uuid가 아닌 `content_key`가 필요하다** | 음성 파일은 임포트 **전에** 만드는데 그때 uuid는 없다. 자연키가 없으면 재임포트마다 중복 행이 쌓이고 오류를 사람에게 보고할 수도 없다 |
| **Zen Maru Gothic 은 일본어 전용** | **한글 글리프가 없다**(실측). 토모는 한국어로 말하므로 **"토모의 말"에 쓸 수 없다.** 한국어의 표정은 폰트가 아니라 크기·자간·줄간으로 만든다 |
| **글자용 토큰을 면으로 재사용 금지** | `text-high`를 버튼 면으로 썼더니 **다크에서 1.07:1**로 버튼이 사라졌다. 글자색 토큰은 테마에 따라 뒤집히는데 짝이 되는 글자색은 안 뒤집혔기 때문 → 면에는 **자기 쌍을 가진 전용 토큰**(`action`/`on-action`) |
| **다크에선 그림자가 분리 수단이 못 된다** | 검은 그림자를 검은 배경에 얹으면 아무 일도 안 일어난다(1.09:1). **밝은 면=그림자 / 어두운 면=테두리.** "테두리 없앤다"는 v3 원칙은 **라이트 한정** |
| **조작 대상은 경계가 보여야 한다** | 카드(그릇)는 면·그림자로 충분하지만 **버튼·입력·토글은 테두리 필수**(비텍스트 3:1). 흰 버튼 vs 오프화이트 배경은 1.07:1 |
| **앰버는 라이트 배경에서 3:1이 물리적으로 불가** | `#F5B942`는 중간 명도라 흰 배경 대비 **최대 1.9:1**. → **색이 아니라 형태로 푼다** — 앰버 진행바를 폐기하고 **우표 도장**으로 대체(낱개가 형태로 분리되어 대비에 의존하지 않음) |
| **미완성은 「곧 열려요」가 아니라 「안 보이게」** | `곧 열려요`는 **코스 단위에만** 쓴다(5개 코스가 있다는 사실은 보여주기로 했으므로). 코스 **아래** 단위(난이도·영역·급수)는 **아예 노출하지 않는다** — 화면마다 반복되면 앱이 미완성으로 보이고, **사용자는 없는 걸 아쉬워하지 않는다.** 🔴 **미공개 ≠ 잠금**: 잠금은 *보이는데 못 감*(자격 판단), 미공개는 *아예 안 보임*. `is_published` 는 **아직 안 만든 것에만** 쓴다 |
| **비즈니스는 우리가 검증 가능한 선까지 채운다** | 대표님 결정은 *"현재는 6명의 직원이 검증"* 이었는데 검토 문서에 *"일본인 감수 전 출시 금지"* 로 **더 세게 적혀 있었다**(2026-07-23 정정). → **입문~중급은 국제교류기금 교재로 대조 검증 가능** → MVP에 포함. **고급(접대·교섭)만 미공개.** 감수자 확보가 출시 일정을 잡지 않는다 |
| **시중 교재는 「사람이 눈으로 보는 검증」에만 쓴다** | 아이디어·사실은 저작물이 아니고 JLPT 목록은 **선택의 폭이 좁아 창작성이 낮다**(출판사별 목록이 크게 겹치는 건 저작이 아니라 시험의 성질). **원리상으로는 참고가 가능하다.** 그런데 실무에서 **목록을 열어 놓고 고르면 선택이 수렴**해 편집을 재현하게 되고, *"참고만 했다"* 를 입증할 방법이 없다. 🔴 **결정타는 대체재가 이미 있다는 것** — Tanos가 같은 정보를 CC BY로 준다. **회색지대를 밟을 이유가 없다.** 허용은 ①난이도 감각 검증 ②주제 누락 확인 둘뿐 |
| **후리가나 점프 방지 = 루비 슬롯 높이 고정 + opacity 전환** | 토글을 껐다 켜도 본문 글자의 세로 위치가 **1px도 안 움직여야** 한다(PRD 8.4). 루비 슬롯을 `display:none`으로 회수하면 점프가 난다 → **높이는 항상 확보하고 opacity만 전환.** 실측: 한자 포함 예문 19글자 top이 ON↔OFF에서 **0px 변화**. `Ruby.jsx`가 이 프로젝트 최대 재사용 자산(단어·지문·퀴즈·오답노트 전부에 들어감) |
| **RN 개발자는 웹 번들러 설정에서 막힌다** | 무스부가 화면 로직(렌더러·카드·데이터)은 완성했으나 **`vite.config.js`(RN→RN Web alias)와 엔트리(index.html·main.jsx)를 빠뜨려** 서버가 안 떴다. RN Web은 config 없이는 아예 안 돈다 → **Expo 정식 이식 때 이 배선을 expo 쪽으로 다시 써야 함** |
| **반투명 배경 위 대비는 「합성」해서 재야 한다** | `rgba(...,0.18)` 을 불투명으로 읽으면 **멀쩡한 요소가 1.57:1로 미달 판정**된다(실제 9.88:1). 아토도 `color-mix` 를 건너뛰는 파서 때문에 반대 방향 오판을 했다. → **대비 측정기는 ①알파 합성 ②`color(srgb)` 표기 둘 다 처리해야 한다.** 계측기가 고장 나 있던 사례(사양서 5.1 ②) |
| **토모는 결제 화면에 넣지 않는다** | 12장이 *"강제 결제 유도 없음"* 을 못 박았는데, **캐릭터로 결제를 설득하는 건 같은 압박을 더 부드러운 얼굴로 하는 것.** 특히 44번(무료 유지 확인)에 넣으면 *"안 사서 아쉬워하는 것처럼"* 읽힌다 — **무료를 고르는 게 미안해지면 안 된다** |
| **JLPT는 5급수 전부 열고, 각 300~500단어만 채운다** | 급수 잠금을 폐기했으므로 **어느 급수든 눌린다** → 비어 있으면 초보가 첫 화면에서 빈 화면을 본다(철학 정면 위반). 그렇다고 추정치(N5 800 ~ N1 10,000, 누계 4,550+)를 다 채우면 출시를 못 한다. → **"급수를 다 채운다"가 아니라 "급수마다 시작할 만큼 채운다".** 제작 순서는 **N5부터**(사용자가 만나는 순서) |
| **위가 가능한 이유 = 분모를 우리 것으로 정했기 때문** | 진행률 분모를 **"우리 앱에 실린 단어 총수"** 로 정했으므로 300개만 있어도 `N5 단어 120/300 수집`이 정상 동작한다. 외부 추정치(2,250)를 분모로 뒀다면 300개만 넣었을 때 진행률이 13%에서 시작해 이상해 보였을 것 — **분모 결정이 콘텐츠 분량 문제까지 같이 풀었다** |
| **한글 발음은 A안(청음=격음 고정)** | `かんこく`→**칸코쿠**. 국어원 표기법(간코쿠)은 같은 가나가 자리에 따라 달라져 **초보가 가나↔한글 대응표를 세울 수 없다.** 이 필드는 **빨리 떼야 할 보조바퀴**이므로 정확한 한국어 표기보다 **대응의 일관성**이 우선. 규칙이 결정적이라 **번복 비용은 스크립트 1회** |
| **망설임은 「글자」가 아니라 「멈춤」으로 쓴다** | TTS는 `えーと、`를 **글자 그대로 「에-토」**라고 읽어 대화가 어색해진다. 뒤에 **`……。`**(삼점 리더+마침표)를 붙이면 실제 침묵이 생겨 자연스러워진다. **이 규칙 하나로 성우 녹음이 불필요해졌다.** ⚠️ 엔진을 바꾸면 다시 청취 확인 |
| **Tanos는 `source`가 아니라 `note`에 적는다** | 라이선스가 CC BY로 풀렸다고 `source=tanos_ccby`를 찍으면, 400건 중 238건에 그게 남아 **"우리는 Tanos 목록을 옮긴 앱"** 이 된다. 같은 사실이라도 **적는 자리가 뜻을 바꾼다** — `source`는 *"값을 어디서 가져왔나"*, `note`는 *"우리가 고른 뒤 무엇으로 대조했나"*. 선정의 주 원천은 **JF 교재 축으로 고정**(교재만이 "실제로 가르치는 순서"를 담는다) |
| **교차검증 판정은 사람이 적지 않는다** | 손으로 「Tanos N4 일치」라고 적으면 **그 문장 자체가 또 검수 대상**이 된다. 검증하려고 만든 것이 검증 대상이 되면 의미가 없다 → 참조본과 대조해 **기계가 `note`에 찍는다**. 그래서 참조본을 개선하면 400건 판정을 **전량 재생성**할 수 있다 |
| **「미확인」을 「일치」로 반올림하지 않는다** | Tanos 참조본(.mem)은 바이너리라 추출이 불완전해 **93건이 미확인**으로 남았다. 이걸 일치로 적으면 숫자는 예뻐지지만 **어느 93건이 미검증인지 영영 알 수 없게 된다.** 못 본 것은 못 봤다고 적는다 |
| **결제 등록보다 청취를 먼저 했다** | 카드부터 만들었으면 *"등록해놨는데 안 쓰네"* 가 될 뻔했다. **판단에 필요한 최소한을 먼저 확인**하고 그다음에 계정·비용을 건드린다 |
| **오답 피드백에 `O`/`X`를 쓰지 않는다** | `O`/`X`는 **채점의 기호**인데 우리는 채점하는 앱이 아니다(1.3). **등불은 심판하지 않고 비춘다** — 오답이면 토모가 정답 쪽을 비춘다(14.2 "비추는 대상만 변화"와 맞물림). 🔴 단 **판정은 문구가 명시적으로** 나르고, **틀렸다고 토모를 어둡게 하지 않는다** |
| **뉴스 목록에 실사진을 쓰지 않는다** | 저작권보다 **오해**가 더 큰 이유다. 뉴스는 **사실 보도**라 비슷한 무료 이미지를 붙이면 사용자는 **그 사건의 사진으로 읽는다** → 학습 앱이 오보의 통로가 된다. 대신 **픽토그램**(분류만 전달, 사실을 주장하지 않음) + **한국어 주제 라벨** |
| **목록에 한국어를 넣는 건 해석 의존이 아니다** | **목록은 "고르는" 화면이지 "읽는" 화면이 아니다.** 8.4가 해석을 문장 탭으로 뺀 건 *지문을 읽는 중* 기대는 걸 막기 위함. **무엇을 읽을지 고르는 단계에서 내용을 모르게 두는 건 도움이 아니라 방해** |
