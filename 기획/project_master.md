## 0. 용어 안내

이 문서에서 "코스"는 학습 목적별로 분리된 커리큘럼 단위(JLPT/여행 회화/비즈니스/뉴스·시사/전래동화)를 가리킴. 기획 초기에는 "트랙"이라는 용어를 사용했으나, 온보딩 화면 목업을 검토하는 과정에서 일반 사용자에게 낯선 외래어라는 지적이 나와 "코스"로 전면 변경함(듀오링고 등 기존 앱에서도 동일 개념에 "코스"를 사용해 친숙함). 이 문서 전체에서 "코스"로 통일되어 있으며, 과거 대화나 이전 버전 파일에 "트랙"이라는 표현이 남아있다면 모두 "코스"와 동일한 의미임.

## 1. 프로젝트 배경 및 계기

대표자 본인이 기존 일본어 학습 앱(듀오링고)을 사용하며 겪은 불편함에서 프로젝트가 시작됨.

**직접 겪은 불편함 2가지**
1. XP(경험치)를 모두 소진했을 때 강제로 결제를 유도하는 흐름 — 학습 의지가 있음에도 결제 화면으로 막힘
2. 강제로 재생되는 리워드 광고 — 학습 흐름을 방해함

이 경험을 바탕으로 "학습 의지를 막지 않는" 앱을 만들겠다는 목표로 기획을 시작함.

---

## 2. 핵심 철학

> **학습 의지를 막지 않는다**

- XP 소진식 강제 결제 유도 없음
- 강제 재생 리워드 광고 없음
- 무료 사용자에게도 전체 콘텐츠 접근 허용 (완전 차단 없음)
- 구독은 "기능을 여는 것"이 아니라 "편의를 사는 것"으로 설계 (광고 제거, 오프라인 저장, 상세 통계 등)

## 3. 타깃 사용자 및 페르소나

### 3.1 초기 타깃 정의
학습 목적에 따라 공간을 분리하고 싶다는 아이디어에서 출발:
- JLPT 목적 학습자
- 일상생활·여행 언어 학습자
- 일본 저학년 교과서·전래동화 등 문화 콘텐츠 관심자

### 3.2 확정 페르소나 (Define 단계, 설문 데이터 기반)

**페르소나 1 — 여행러 지은 (27세) · 메인 타깃**
- 목표: 여행 전까지 기본 회화를 스스로 할 수 있는 수준 도달
- Pain: 목적과 무관하게 문법부터 순서대로 배워야 하는 기존 앱 구조
- 근거: 설문 학습 목적 응답 중 90%가 "여행·일상 회화" 선택 (Q2)
- 인용: "단순히 귀찮아지거나 바빠져서" 그만뒀어요 — 설문 이탈사유 최다 응답(35%)

**페르소나 2 — 목표형 준호 (32세) · 서브 타깃**
- 목표: 이직을 위한 JLPT N2 + 실무에 쓸 수 있는 비즈니스 일본어
- Pain: 시험 대비와 실무 표현이 앱 안에서 분리되어 있지 않음
- 근거: 설문 관심 코스에서 JLPT·비즈니스 공동 1위, 각 30% (Q9)
- 인용: "현지에서 사용하는 실용 고급 일본어가 필요합니다" — 자유응답

### 3.3 Problem Statement
> 여행·일상 회화나 시험 등 명확한 목적을 가지고 일본어를 배우려는 학습자는, 기존 앱(듀오링고 등)이 모든 사용자에게 동일한 커리큘럼을 제공하고 꾸준한 학습을 돕는 장치가 부족하기 때문에, 배우고 싶은 마음은 있어도 "바빠지면 자연스럽게 멀어지는" 경험을 반복한다.

### 3.4 As-Is 사용자 여정지도 — "여행러 지은" 기준

| 단계 | 행동 | 생각 | 감정 | 기회 영역 |
|---|---|---|---|---|
| 발견 | 여행 D-30, 급하게 학습 앱 검색·설치 | "금방 기본 회화 정도는 배우겠지" | 기대 | — |
| 첫 학습 | 히라가나부터 순서대로 시작 | "나는 인사말이 급한데 왜 문자부터 배우지?" | 의아함 | 목적 기반 커리큘럼 분기 필요 |
| 중반 (2주차) | 야근으로 3일 접속 안 함, XP 초기화 | "다시 처음부터 해야 하나..." | 부담 | 이탈 후 재진입 장벽 낮추기 |
| 이탈 | 앱 삭제, 여행 D-3에 유튜브로 급하게 검색 | "애초에 여행 회화만 빨리 익혔으면 됐는데" | 후회 | 목적 완료형 짧은 커리큘럼 필요 |

### 3.5 How Might We
1. 사용자가 처음부터 자신의 목적에 맞는 학습 경로를 선택하게 하려면?
2. 며칠 접속하지 않아도 부담 없이 다시 시작하게 하려면?
3. "바빠서 못했다"는 이탈을 막기 위해 학습 단위를 어떻게 쪼개야 할까?
4. 시험·실무처럼 서로 다른 목적을 한 앱 안에서 자연스럽게 넘나들게 하려면?

## 5. 리서치 프로세스 — 가설 → 설문 → 검증

### 5.1 진행 방식
1. 초기 가설 다수 수립 (수익모델/UX/코스/학습지속성 관련, 총 16개)
2. 익명 설문 제작 (Google Forms, 9~10문항) 후 카카오 오픈채팅방(1,216명 규모)에 배포
3. 참여 사은품: 배민 쿠폰 응답자 중 추첨 지급 (연락처는 발송 목적으로만 수집, 발송 후 삭제 원칙)
4. 4일(목~일) 진행, 20명 응답 확보 (목표 50명 대비 40% 달성)
5. 응답 데이터를 Google Sheets로 수집 후 분석

### 5.2 설문 문항 구성 (최종 배포본)
- **섹션 1 (학습 경험)**: Q1 목적 유무와 학습 지속률 / Q2 학습 목적(복수선택) / Q3 목적별 커리큘럼 도움 정도(1~5 척도)
- **섹션 2 (앱 사용 경험·경쟁사)**: Q4 사용 경험 있는 앱(복수선택) / Q5 좋았던 점(복수선택) / Q6 이탈 이유
- **섹션 3 (신규 컨셉 반응)**: Q7 앱 사용 의향 / Q8 구독료(1,900원/연 20,900원) 반응 / Q9 관심 코스

### 5.5 핵심 인사이트 (설문 결과가 기획에 미친 영향)
1. **여행·일상 회화 수요가 압도적** → 코스에서 빠져있던 "여행 회화" 코스을 신설하는 계기가 됨 (6장 참조)
2. **이탈 원인은 광고가 아니라 "습관 형성 실패"** → 광고 제거를 핵심 셀링포인트로 과대 포장하지 않고, 습관 형성 기능(알림, 짧은 세션) 우선순위를 높임
3. **비즈니스 코스이 예상보다 강한 수요** → MVP에서 JLPT와 함께 우선 완성도를 높이는 코스으로 재조정
4. **목적 복수 선택자가 과반(55%)** → 온보딩에서 코스을 하나로 완전히 제한하지 않고, 메인+서브 추천 및 자유로운 전환 구조를 채택하는 근거가 됨 (7장 참조)

- "전래동화로 배우는 거 너무 신박해요. 유명한 만화 대사 같은 것도 있으면 좋겠어요."
- "현지에서 사용하는 실용 고급 일본어가 필요합니다."
- 전반적으로 긍정적 반응 다수 ("화이팅", "접근성을 높여줄 것 같다" 등)

> ⚠️ 표본 20명은 방향성 참고용. 통계적 유의성 확보에는 최소 50명 이상 필요하며, 현재 결과는 확신보다는 방향 판단 근거로 활용 중.

## 6. 학습 코스 구조 (5개, 확정)

| 코스 | 등급/구성 | 비고 |
|---|---|---|
| JLPT 시험 대비 | N5~N1 | 문자·어휘→문법→독해→청해 순서, D-day 카운터 |
| **여행 회화** | 상황별 카테고리 | ★설문 반영 신규 코스, 아래 6.1 참조 |
| 비즈니스 일본어 | 입문~고급 (JLPT 등급과 별개) | 설문에서 JLPT와 공동 1위 관심 코스 |
| 뉴스·시사 | N5~N1 | NHK Web Easy 수준 → 원문 순서 |
| 전래동화 | N5~N1 | 浦島太郎·桃太郎 등, 성인 초급 학습자에게도 유효 |

### 6.1 여행 회화 코스 상세 (옵션 B — 통합형 + 섹션 분리 채택)

코스은 하나이되 내부적으로 두 섹션으로 명확히 구분:

1. **상황별 여행 표현**: 공항·입국심사 / 교통·길찾기 / 숙소 체크인 / 식당·주문 / 쇼핑·계산 / 편의점·약국 / 온천·료칸 / 긴급상황 대처
2. **일본인 일상 표현 TIP**: 여행자가 아니어도 관심 가질 수 있는 실제 구어체 표현 (별도 라벨, 같은 코스 내 위치)

**채택 이유**: 완전 분리형(6코스)은 제작비용 과다, 완전 통합형(라벨 없이 섞기)은 여행 계획자와 일상표현 관심자를 구분 못함. 섹션 라벨 분리로 두 니즈를 하나의 코스에서 충족.

(검토 후 기각한 대안: 옵션 A 완전 통합/무라벨, 옵션 C 별도 코스 분리 6개, 옵션 D 챌린지형 마이크로 코스 — D는 Could 단계 아이디어로 보류)

## 7. 온보딩 진단 테스트 및 코스 개인화

### 7.0 전체 온보딩 화면 순서
스플래시 → **앱 소개 (신규)** → 회원가입·로그인 → 진단 테스트 → 추천 결과 → 레벨 테스트 → 첫 학습 시작

**앱 소개 화면 추가 배경**: 스플래시 직후 바로 회원가입을 요구하면 "이 앱이 뭔지도 모르는데 가입부터"하는 이탈 요인이 됨. 1~2장 분량으로 핵심 가치만 압축 전달 후 하단에 가입 버튼 배치 (1장: 코스별 목적 커리큘럼 소개 / 2장: 강제 결제 없는 핵심 철학).

### 7.1 배경
당초 "선택한 커리큘럼만 볼 수 있게 제한"하는 구조를 검토했으나, 설문 재분석 결과 55%가 목적을 복수 선택한 것으로 확인되어 완전 제한형을 기각. "메인 코스 집중 + 서브 코스 제안 + 언제든 전환" 구조로 조정.

### 7.2 진단 테스트 — 4문항 (약 40초, 시험이 아닌 취향 진단)

| 문항 | 목적 | 결정되는 것 |
|---|---|---|
| Q1. 일본어가 가장 급하게 필요한 순간은? | 목적 파악 (가중치 50%) | 메인 코스 추천 (여행/JLPT/비즈니스/문화·뉴스) |
| Q2. 지금 일본어를 얼마나 알고 있나요? | 현재 수준 파악 | 시작 난이도 (정식 레벨 테스트로 이후 정교화) |
| Q3. 하루에 학습에 쓸 수 있는 시간은? | 학습 강도 파악 | 오늘의 학습 분량, 푸시 알림 빈도 (이탈원인 1위 "바빠서" 대응) |
| Q4. 학습할 때 나를 움직이게 하는 것은? | 동기 유형 파악 | 홈 화면 위젯 노출 순서 (7.4 참조) |

### 7.3 추천 결과 및 전환 구조
- 메인 코스 1개를 크게 추천(Q1 기반) + 서브 코스 작게 함께 제안(복수 목적 대응)
- 홈 화면은 메인 코스 콘텐츠 중심 구성 ("숨김"이 아닌 "기본값 집중")
- 홈 화면 상단/하단 퀵메뉴로 5개 코스 언제든 전환 가능, 온보딩 완료 화면에서 명시적 안내

### 7.4 홈 화면 개인화 — 위젯 순서 조정 (레이아웃 자체는 단일)
완전히 다른 3개 레이아웃 대신, 동일 구조 내에서 위젯(스트릭/진도율/우표) 노출 순서만 Q4 응답 기반으로 재배열.

| Q4 응답 | 상단 배치 위젯 | 심리적 근거 |
|---|---|---|
| 연속 기록이 끊기지 않는 것 | 스트릭 위젯 | 손실 회피(Loss Aversion) |
| 목표에 가까워지는 것 | 진도율 위젯 | 목표 근접 효과(Goal Gradient Effect) |
| 보상을 모으는 재미 | 우표 위젯 | 가변적 보상(Variable Reward) |

> ⚠️ 미검증 가설: Q4 응답이 실제 재방문율에 미치는 영향은 설문으로 확인된 바 없음. 런칭 후 A/B 테스트로 검증 예정. 효과 없으면 고정 순서로 단순화 가능.

## 8. 신규 기능 — 카메라 문구 인식 번역

### 8.1 개요
여행 중 메뉴판·표지판·안내문을 카메라로 비추면 OCR로 텍스트 인식 + 번역 제공. 여행 회화 코스과 연계해 학습 앱만의 차별화 포인트로 설계.

### 8.2 차별화 방향 (구글 번역 등 무료 대안과의 차이)
- 인식된 표현을 여행 회화 코스 학습 콘텐츠와 매칭해 함께 노출
- 인식된 단어를 탭하여 즉시 단어장에 저장 가능 (9장 연계)
- "이 표현, 여행 회화 3과에서 배운 표현이에요" 식 학습 연계 알림

### 8.3 기술 구현 방향
직접 OCR·음성인식 엔진 개발은 비현실적(ML 전담 인력·수개월 소요) → 검증된 외부 API 연동으로 해결 (Google Cloud Vision + Translate, 네이버 파파고 API, Google Speech-to-Text, OpenAI Whisper 등). 개발자 1명 기준 프로토타입 1~2주 내 가능.

### 8.4 단계적 출시 계획
| 단계 | 범위 |
|---|---|
| MVP (Should) | 카메라 문구 인식(OCR + 번역) |
| v1.1 (Could) | 음성 통역 (짧은 문장) |
| v1.2+ | 실시간 대화 통역 |

### 8.5 리스크
구글 번역 등 무료 대안이 이미 존재 → 학습 콘텐츠 연계(단어장 자동 저장, 코스 매칭)로 차별화하지 못하면 단순 번역 도구로 인식되어 이탈 유발 가능.

## 9. 나만의 단어장 (통합 단어장 시스템)

### 9.1 구조 — 통합 저장 + 태그 필터링 (기본 태그 + 커스텀 태그)
앱 내 모든 학습 콘텐츠에서 저장한 단어가 하나의 단어장에 모이되, 태그로 필터링 가능.

- **기본 태그 (5개, 학습 코스와 동일)**: JLPT / 여행 회화 / 비즈니스 / 뉴스·시사 / 전래동화
- **커스텀 태그(신규)**: 사용자가 직접 이름 지어 추가 가능(예: "출장 필수표현"), 기본 태그와 시각적으로 구분
- **태그 부여 방식**: 레슨·퀴즈·오답노트에서 저장 → 현재 학습 코스로 자동 태그(변경 없음) / 카메라 인식으로 저장 → 저장 위치 선택 화면에서 기본+커스텀 태그 중 1개를 직접 선택(단일 선택만 허용, 카메라는 코스 맥락이 없어 예외 처리)
- **재분류**: 어떤 단어든 단어장에서 언제든 태그를 바꿀 수 있음(카메라 인식 단어에 한정하지 않고 전체 적용)

**채택 이유**: 완전 분리형(코스별 단어장 각각)은 카메라 인식 단어의 저장 위치가 애매해짐. 완전 통합형(태그 없음)은 시험 대비 등 목적별 복습이 어려워짐. 카메라만 수동 선택하게 한 이유는 나머지 경로는 코스 맥락이 이미 명확해 자동 태그가 정확하지만 카메라는 코스와 무관하게 언제든 켤 수 있어 자동 추정이 부정확할 수 있기 때문. → 저장은 한 곳에, 조회는 태그 필터로 해결.

**활용 연계**: 단어장 PDF는 태그 필터가 적용된 상태 그대로 생성 가능 (예: "이번 주 여행 회화 단어만 PDF로"). ⚠️ **우표와는 별개** — 단어장 전체 PDF는 우표를 소비하지 않고 월 횟수(무료 월 3회 / 구독 무제한)로 제한됨(11장 참조). **우표 소비처는 "오늘의 학습 요약 PDF" 전용**.

### 9.2 단어 저장 인터랙션 — 탭 → 뜻 팝업 → 저장 버튼 (앱 전체 공통)
단어를 탭하면 뜻·읽는법이 담긴 팝업이 뜨고, 팝업 안에 "단어장에 저장" 버튼 배치. 뜻 확인(학습)과 저장(수집)을 한 번의 인터랙션으로 동시 해결.

**기각한 대안**: 원탭 즉시저장(실수 저장, 뜻 미확인), 롱프레스 저장(발견성 낮음, 모바일 오작동)

**자동 태그 규칙**: 저장 시점에 사용자가 보고 있던 화면의 코스을 자동 태그. 별도 선택 과정 없음.

**적용 범위**: 학습 본문(JLPT 독해·전래동화·뉴스 기사), 퀴즈 문제·오답노트, 카메라 인식 결과 화면 — 전체 동일 패턴 적용.

## 10. 학습 루프 및 오늘의 학습 요약

### 10.1 학습 루프 구조 (전 코스 공통 골격)
오늘의 학습 시작 → 레슨 콘텐츠 학습(단어 탭 저장 가능) → 퀴즈 진행 → 정답/오답 분기(오답 시 오답노트 자동저장) → 우표 적립 → 오늘의 학습 요약 → 다음 레슨 또는 홈으로.

**코스 간 공통점/차이점**: 전체 골격은 5개 코스 모두 동일(퀵메뉴 전환 시 재학습 비용 없앰). "레슨 콘텐츠 학습" 단계의 화면 형식만 콘텐츠 성격에 따라 내부적으로 갈림 — 읽기형(뉴스·시사, 전래동화: 지문→단어탭저장→이해퀴즈), 구문·어휘형(여행회화, 비즈니스: 표현카드→바로퀴즈), 혼합형(JLPT: 문자·어휘는 구문형, 독해는 읽기형).

### 10.2 오늘의 학습 요약 화면
레슨 완료 시 한 화면에서 제공: ① 오늘 배운 단어(저장 목록) ② 오답노트에 추가됨(질문+정답, 후리가나 항상 포함) ③ 오늘의 조언(오답 패턴 기반 1줄, 규칙 기반 MVP 구현 가능). 우표 진행바 상시 노출, 목표치(7개) 도달 시 PDF 다운로드 버튼 활성화(미달 시 "N개 더 모으면" 안내와 함께 비활성). 구독자는 매달 대량 우표(약 50장 분량) 자동 증정으로 사실상 매일 다운로드 가능 (11장 참조).

### 10.3 학습 기록 (MY 탭 신규 메뉴)
날짜별 "오늘의 학습 요약"을 모아보는 목록 화면. MY 탭 내 신설, 탭하면 해당 날짜 요약 화면이 열림. PDF용으로 이미 저장되는 일별 요약 데이터를 재사용해 신규 저장 비용 없이 구현 가능 — 성장 기록·재방문 동기로 작용.

### 10.4 읽기 도움 토글 (후리가나 + 한글 발음)
후리가나와 한글 발음을 하나의 토글로 묶어 제공(필요 사용자군이 대부분 겹쳐 단순화, 3단계 토글은 Could로 보류).
- **기본값은 항상 켜짐(ON)**: 오답노트는 "몰랐던 것을 다시 보는" 공간이라 읽기 지원이 기본으로 필요하다는 원칙에 따라, 앱 전체(레슨·단어장·오답노트·PDF)의 토글 기본값을 켜짐으로 통일. 오답노트만의 별도 예외를 두지 않고 "기본 ON + 언제든 끄기 가능"이라는 단일 규칙으로 단순화
- 화면별 빠른 토글 + MY › 설정 기본값(레슨·단어장·오답노트·PDF 공통 적용, 초기값 ON)
- PDF는 다운로드 시점의 토글 상태를 캡처, 이후 설정 변경과 무관하게 유지 — 후리가나 없이 학습하고 싶은 사용자는 토글을 꺼서 PDF에도 반영 가능

## 11. 수익 모델 (확정)

| 단계 | 기간 | 제공 내용 |
|---|---|---|
| 1. 프리미엄 체험 | D1~D7 | 광고 없음, 전체 콘텐츠 잠금 해제, PDF 다운로드 무제한 |
| 2. 무료 플랜 | D8~ | 전체 콘텐츠 계속 이용 가능(제한 없음) + 배너 광고. 학습 흐름 자체에는 어떤 대기·제한도 없음 |
| 3. 구독 플랜 | 월 1,900원 / 연 20,900원 | 광고 제거 + PDF/내보내기 대폭 확대 |

**설계 변경 이력**: 당초 "레슨 간 3초 대기+복습카드"를 무료 사용자 마찰 장치로 검토했으나, 레슨마다 반복되는 마찰이 설문 이탈 1위 원인("바빠서·귀찮아서" 35%)을 자극할 수 있다고 판단해 기각. 마찰 지점을 학습 흐름 밖 PDF/내보내기 시점 하나로 단순화.

**PDF/내보내기 할당량** (v2.8 — PDF는 우표와 분리, 종류 무관 통합):

| 항목 | 무료 플랜 | 구독 플랜 |
|---|---|---|
| **전체 PDF (요약·오답노트·단어장·독해 합산)** | **월 5회 통합** (매월 1일 리셋) | **무제한** |

**무료 사용자 제한 원칙**: 완전 차단이 아닌 "기회는 주되 약간의 불편함" — 열람·학습은 언제나 무제한, 결과물을 소장하는 PDF 다운로드에만 상한. 종류별 쿼터는 설명이 복잡해 폐기하고 "이달 PDF 5번" 단일 규칙으로 통일.

**우표 시스템 (v2.8 — 컬렉션 모델)**: 결제 요소 아님 — **"오늘의 학습" 1단위 완료당 우표 1개** 적립(모듈 단위 아님). **우표는 소비하지 않고 영구 누적**되며, **14장마다 편지 1통**이 온다(첫 편지는 **3장**으로 온보딩 가속). 편지는 토모의 감성 리워드로 PDF와 **분리**. 유료 구매 불가.

**우표를 소비처와 묶지 않는 이유(옛 7/5/10 폐기)**: 우표를 써서 PDF를 사면 결국 게임 재화·포인트 상점이 되어 "밝혀주되 끌지 않는다"(1.3) 철학과 멀어짐. PDF는 결과물 소장 기능이라 **수익 축(구독)**에, 우표/편지는 **몰입 리워드 축**에 두어 분리. **구독 가치 = 기능**(광고 제거·PDF 무제한), 우표 350장 대량 증정은 **폐지**(비소비 재화라 무의미 + "돈으로 성취 구매" 인상 방지).
우표·편지는 **학습 콘텐츠·기능을 여는 열쇠로 쓰지 않음**. (기각: 우표 소비 상점 / 캐릭터 커스터마이징 — 14.2 위배 / 스트릭 프리즈 — 손실회피 자극으로 철학 충돌 / 구독 전용 기능 해금 — 구독 가치 훼손 / 우표 유료 구매)

## 12. 기능 범위 (Scope) — MoSCoW

### Must (MVP 필수)
- 온보딩: 스플래시 → 앱 소개 화면(신규) → 회원가입 → 4문항 진단 테스트 → 메인+서브 코스 추천
- 회원가입·로그인(소셜 로그인), 레벨 테스트
- 5개 코스별 커리큘럼 학습 (읽기형/구문·어휘형/혼합형)
- 게임형 퀴즈(객관식, 받아쓰기, 짝 맞추기)
- 학습 진도 저장 및 퀵메뉴 코스 전환
- 7일 프리미엄 체험 → 무료(배너광고)/구독(월 1,900원) 전환
- 우표 적립 시스템 → 학습 요약 PDF 다운로드
- 오늘의 학습 요약 화면 (오늘 배운 단어·오답노트·학습 조언)
- 오답노트 (자동저장, 읽기 도움 토글 기본 ON으로 후리가나·발음 표시)
- 홈 화면 (스트릭·오늘의 학습·진도, Q4 기반 위젯 순서 개인화)
- 나만의 단어장 (통합 + 기본/커스텀 태그 필터링, 태그 재분류 가능)
- 단어 탭 → 뜻 팝업 → 저장 인터랙션 (앱 전체 공통)
- 읽기 도움 토글 (후리가나+한글발음)

### Should (출시 직후)
- 카메라 문구 인식 번역 (OCR + 번역 API)
- 스피킹 퀴즈 (TTS 발음 비교)
- 상세 학습 통계·오프라인 저장 (구독자용)
- 푸시 알림 (학습 리마인드)
- 학습 기록 (MY 탭, 일별 요약 모아보기)
- 나만의 단어장 전체 PDF 내보내기 (무료 월 3회 / 구독 무제한)
- 장문 독해·전래동화 PDF 내보내기 (무료 월 3회 / 구독 무제한)

### Could (여유 있을 때)
- 음성 통역 (짧은 문장)
- 만화 대사 기반 학습 콘텐츠 (자유응답 요청)
- 랭킹/리더보드
- 여행 챌린지형 코스 ("3일간의 도쿄 여행" 시나리오형)

### Won't (이번 범위 제외)
- XP 소진식 강제 결제 유도
- 강제 재생 리워드 광고
- 유료 우표 구매
- 실시간 대화 통역 (v1.2 이후로 연기)

## 15. 포트폴리오 진행 로드맵 (UX/UI 포트폴리오 병행 목적)

이 프로젝트는 실제 창업 아이템이자 UX/UI 포트폴리오 사례로도 활용 예정. 프로세스 단계:

| 단계 | 상태 | 산출물 |
|---|---|---|
| 1. Discover (문제 발견) | ✅ 완료 | 계기, 가설, 설문 20명 검증 |
| 2. Define (문제 재정의) | ✅ 완료 | Problem Statement, 페르소나 2명, As-Is 여정지도, HMW |

| 4. Ideate (정보구조·플로우) | ✅ 완료 | To-Be 여정지도 ✅, IA(사이트맵) ✅, 온보딩·학습루프·구독전환·카메라번역 플로우 전체 완료 |
