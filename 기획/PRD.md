## 0. 용어 안내

이 문서에서 "코스"는 학습 목적별로 분리된 커리큘럼 단위(JLPT/여행 회화/비즈니스/뉴스·시사/전래동화)를 가리킴. 기획 초기에는 "트랙"이라는 용어를 사용했으나, 일반 사용자에게 낯선 외래어라는 점을 고려해 온보딩 화면 목업 검토 과정에서 "코스"로 전면 변경함. 듀오링고 등 기존 학습 앱에서도 동일 개념에 "코스"를 사용하고 있어 사용자에게 친숙함.

## 1. 개요 (Overview)

### 1.1 한 줄 정의
목적별로 분리된 커리큘럼과 강제성 없는 학습 경험을 제공하는 일본어 학습 앱

### 1.2 배경 (Why)
대표자 본인이 기존 학습 앱(듀오링고)을 사용하며 겪은 두 가지 불편함에서 출발함.

- XP 소진 시 강제 결제를 유도하는 흐름에서 느낀 불쾌감
- 강제로 노출되는 리워드 광고로 인한 학습 흐름 방해

이 가설을 20명 대상 설문으로 검증한 결과, 예상과 다른 인사이트도 함께 발견됨 (3장 참조).

### 1.3 핵심 철학
> 학습 의지를 막지 않는다

무료 사용자에게도 완전한 콘텐츠 접근을 제공하고, 구독은 "편의를 사는 것"이지 "기능을 여는 것"이 아니게 설계한다.

## 4. 학습 코스 구조 (5개 코스)

기존 4개 코스에 여행 회화 코스을 추가하여 총 5개 코스으로 확정.

| 코스 | 등급/구성 | 비고 |
|---|---|---|
| JLPT 시험 대비 | N5~N1 | 문자·어휘→문법→독해→청해 순서 |
| 여행 회화 | 상황별 카테고리 | ★신규 — 아래 상세 참조 |
| 비즈니스 일본어 | 입문~고급 (**J 라벨 병기**) | 설문에서 JLPT와 공동 1위 관심 코스. **BJT 정합** — 4.2 참조 |
| 뉴스·시사 | N5~N1 | NHK Web Easy 수준→원문 순서 |
| 전래동화 | N5~N1 | 성인 초급 학습자에게도 유효 |

### 4.1 여행 회화 코스 상세 설계

**구조 방식**: 통합형 + **카테고리 내 라벨 분산** (옵션 B′ — 2026-07-20 개정)

코스는 하나이며, 아래 8개 카테고리가 여행 동선 순서로 구성됨:
- 공항·입국심사 / 교통·길찾기 / 숙소 체크인 / 식당·주문 / 쇼핑·계산 / 편의점·약국 / 온천·료칸 / 긴급상황 대처

**일본인 일상 표현 TIP**은 별도 섹션으로 떼어 두지 않고, **각 카테고리 안에 관련 TIP을 섞어 배치**한다. 단 **`TIP` 라벨은 그대로 유지**하고, **"TIP만 모아보기" 필터**를 제공한다.

**개정 이유**: 당초 두 섹션으로 분리(옵션 B)했으나, 실제로는 **카테고리마다 그 상황에 맞는 TIP이 필요**하다(식당 카테고리엔 식당에서 쓰는 구어체 TIP). 섹션을 떼어 놓으면 학습 맥락과 TIP이 분리되어 효용이 떨어짐.
**원래 우려의 해소**: 옵션 B를 택했던 이유는 "완전 통합형(라벨 없이 섞기)은 여행 계획자와 일상표현 관심자를 구분하지 못한다"였음. 이번 개정은 **라벨을 유지하고 TIP 전용 필터를 두므로**, 일상표현에만 관심 있는 사용자도 TIP만 골라 볼 수 있어 그 우려가 해소됨. (라벨 없이 섞는 옵션 A는 여전히 채택하지 않음)

### 4.2 비즈니스 일본어 코스 상세 설계 — **BJT 정합** (2026-07-22 확정)

**방침 한 줄**: 🔴 **"BJT 정합이지 BJT 대비가 아니다."** BJT를 **목표가 아니라 자(尺)로** 쓴다.

#### 4.2.1 배경 — 왜 BJT를 끌어오는가

비즈니스 코스는 **전 영역 `⚠️검증필요`** 상태로 막혀 있었다(리서치 `05_비즈니스`). 현지 실사용·세대/업계 적합성이 검증되지 않아 **일본인 감수 전 확정·출시 금지**가 규칙이다.
BJT(ビジネス日本語能力テスト, 日本漢字能力検定協会)의 **공식 문항 유형**을 근거로 삼으면 판정 질문이 바뀐다.

| | 도입 전 | 도입 후 |
|---|---|---|
| 판정 질문 | *"우리가 고른 이 표현, 현지에서 진짜 쓰나?"* | *"이 문항이 공식 시험 유형에 맞나?"* |
| 판정 주체 | **현직 일본인만 가능** | 유형 정합성은 **우리도 판정 가능** |

⚠️ **감수가 불필요해지는 것이 아니다.** 경어를 잘못 쓰면 오류가 아니라 **실례**이고, 그건 유형을 바꿔도 사라지지 않는다.
**감수가 없어지는 게 아니라 범위가 좁아져 빨라진다** — 감수자가 "표현의 자연스러움"만 보면 된다.

#### 4.2.2 BJT 구조 (참고 사실)

3부 구성: **제1부 聴解 / 제2부 聴読解 / 제3부 読解**. 0~800점 **스코어제**(합불 아님), 레벨 **J5→J4→J3→J2→J1→J1+**.
제2부 聴読解는 ①状況把握 ②資料聴読解(그래프·표·광고) ③総合聴読解(견적서·결산표·**이메일 화면**)로 나뉜다.

> 🔴 **BJT에는 말하기·쓰기 시험이 없다.** 전부 듣기·읽기다.
> 따라서 **모의면접·메일 작성은 BJT의 일부가 아니라 우리 고유 기능**이며, 4.2.5에서 별도로 정의한다.

#### 4.2.3 난이도 라벨 — **약한 표기(B안)** 채택

난이도 축은 기존대로 `입문 / 초급 / 중급 / 고급`을 유지하고, **J 라벨을 병기**한다.

```
[입문 · J5 목표]  [초급 · J4 목표]  [중급 · J3 목표]  [고급 · J2~ 목표]
```

**🔴 "J3 상당"이라 단정하지 않고 "J3 목표"로 표기하는 이유**
BJT 레벨은 **응시자 점수 구간**이지 콘텐츠에 매기는 등급이 아니다(J1+ = 600점 이상, J1 = 530~599).
우리가 임의로 "이 레슨은 J3 상당"이라 붙이면 **그 매핑 자체가 또 하나의 미검증 주장**이 된다 — 급수별 목표 단어 수와 같은 함정이다.
→ **근거가 생기기 전까지는 약하게 쓰고**, 감수자를 확보하면 매핑도 함께 검증받아 표기를 강화한다.

**기각안**
- (A) `J3 상당` 단정 표기 → 근거 없는 단정
- (C) 레벨 매핑을 아예 안 함 → 안전하지만 "내 수준이 어디인가"를 알려주는 이점이 사라짐

#### 4.2.4 자료 기반 문항 신설 (BJT 総合聴読解 유형)

**견적서·결산표·이메일 화면 등 업무 문서를 보면서 음성을 듣고 답하는** 문항을 추가한다.
실무에서 실제로 하는 일(문서를 보며 상사의 말을 듣는 것)이라 학습 가치가 높다.

- **신규 화면 없음** — **48번 문서 템플릿형**이 이미 그릇이다
- **신규 퀴즈 유형 없음** — 기존 `청해형`에 **자료 이미지가 붙는 형태**
- 데이터: `questions.asset_url` **컬럼 1개 추가**(스키마_설계 ③) — 현재 문제 테이블엔 음성만 있고 이미지 칸이 없다
- ⚠️ **제작비가 오른다** — 그래프·견적서 이미지를 만들어야 해서 JLPT 청해보다 비싸다

#### 4.2.5 모의면접 · 메일 작성 — BJT 밖의 기능

| 요청 | 처리 | 이유 |
|---|---|---|
| **모의면접(롤플레잉)** | **49번 대화 시뮬레이션형 확장**. 🔴 **채점하지 않는다** — 모범 답변 대조 + 자가판정. Should | 스피킹 유사도 판정은 이미 **폐기**했다(Lo-fi 3차 수정). 자유 응답은 더더욱 판정 불가. **"테스트"가 아니라 "연습"** 으로 포지셔닝 — 꺾지 않는 철학과도 정합 |
| **메일·문서 작성** | **48번에 통합.** 자유 작문이 아니라 **기존 퀴즈 3유형으로 구성** — 빈칸 채우기 / 문형 선택 / **순서 배열형**(인사→용건→맺음) | MVP에서 자유 작문 채점은 불가능. 기존 유형으로 충분히 대체되므로 **새 기능이 필요 없다** |

#### 4.2.5-1 🆕 감수 범위 — **우리가 검증 가능한 선까지 채운다** (2026-07-23 확정)

**경위 정정**: `코스별_플로우_검토.md` 11번이 *"일본인 채용 후 감수 전까지 확정·출시 금지"* 로 적혀 있으나, 이는 대표님 결정(*"추후에 일본인 고용 예정. **현재는 6명의 직원이 꼼꼼하게 검증하도록 하자**"*)보다 **강하게 기재된 것**이다. 아래로 정정한다.

| 난이도 | 우리 검증 | 근거 |
|---|---|---|
| **입문 · 초급 · 중급** | ✅ **가능 → MVP에 채운다** | 인사·메일 서두/맺음·전화 정형구·경어 3분류는 **국제교류기금 교재에 실려 있다.** 대조로 검증된다 — N5 단어에 쓴 방법과 동일 |
| **고급**(접대 · 교섭 · 업계 뉘앙스) | ❌ 어려움 → **미공개**(4.2.5-2) | 현지 실사용 감각이 필요. 리서치에서도 *"고급 실사용 표현이 상대적으로 얕음"* 으로 이미 확인됨 |

→ **비즈니스는 MVP에 들어간다.** 감수자 확보 여부가 출시 일정을 잡지 않는다.

#### 4.2.5-2 🔴 미완성은 「곧 열려요」가 아니라 **보이지 않게** 한다 (2026-07-23 신설 · 전 코스 공통 규칙)

**`곧 열려요` 표기는 코스 단위(11.0)에만 쓴다.** 코스 안의 난이도·영역·급수에는 쓰지 않는다.

| | 표현 | 쓰는 곳 |
|---|---|---|
| **코스** 단위 | `곧 열려요` **표시** | 뉴스·전래동화. **5개 코스가 있다는 사실 자체를 보여주기로 했으므로**(11.0) 감추면 안 된다 |
| 그 **아래** 단위 | **아예 노출하지 않음** | 비즈니스 「고급」, 아직 안 채운 급수 등 |

**왜 아래 단위는 감추는가**
- `곧 열려요`가 화면 여기저기에 반복되면 **앱이 미완성으로 보인다.** 코스 목록에서 한 번 보는 것과, 들어가는 곳마다 보이는 것은 다르다.
- 사용자는 **없는 것을 아쉬워하지 않는다.** 있는데 못 쓰는 것을 아쉬워한다.

**🔴 「미공개」와 「잠금」은 다르다 — 혼동하면 폐기한 결정이 되살아난다**
| | 사용자가 보는 것 | 신호 |
|---|---|---|
| **잠금** ❌ 폐기됨 | 보이는데 못 들어감 | *"너는 아직 자격이 없다"* → 학습 의지를 꺾는다(1.3) |
| **미공개** ✅ 이번 규칙 | **아예 안 보임** | 그냥 **아직 없는 것**. 자격 판단이 없다 |

**구현**: `course_levels`·`course_tracks` 에 **`is_published`** 를 둔다. `false`면 목록·셀렉터·검색 어디에도 나오지 않는다.
> ⚠️ **`is_published`는 「우리가 아직 안 만든 것」에만 쓴다.** 만들어 놓고 **조건부로 여는 용도로 쓰지 않는다** — 그 순간 이름만 바꾼 잠금이 된다. (2.9 `is_locked`를 아예 만들지 않기로 한 것과 같은 이유)

#### 4.2.6 바뀌지 않는 것 (중요)

- **코스 이름** — "비즈니스 일본어" 유지. **"BJT 대비"로 바꾸지 않는다**
- **해설 축** — `상황 적절성·정중도` 유지(`코스별_플로우_검토.md` 1번). 문법적 정오로 되돌리지 않는다
- **학습 루프·화면 구조** — 변경 없음
- **BJT를 보지 않는 사용자에게 어떤 부담도 지우지 않는다**

> **근거**: 설문에서 30%가 "비즈니스 관심"이라 답한 것이 *"BJT를 보고 싶다"* 는 뜻은 아니다. 대다수는 **회사에서 쓸 일본어**를 원한다.
> D-day를 "선택적 동기 장치이지 학습 전제조건이 아니다"로 못 박은 것과 **같은 논리**다(`코스별_플로우_검토.md` 7번).

#### 4.2.7 D-day 연동
**46번 시험일 설정 모달을 그대로 재사용**한다. JLPT 시험일 ↔ 여행 출발일 ↔ **BJT 응시일** — 같은 화면, 같은 규칙(미입력이어도 학습에 지장 없음).

## 5. 신규 기능 — 카메라 문구 인식 번역

### 5.1 개요
여행 중 메뉴판, 표지판, 안내문 등을 카메라로 비추면 OCR로 텍스트를 인식하고 번역을 제공하는 기능. 여행 회화 코스과 연계하여 학습 앱만의 차별화 포인트로 설계.

### 5.2 차별화 방향 (단순 번역 앱과의 차이)
- 인식된 표현을 "여행 회화" 코스의 학습 콘텐츠와 매칭하여 함께 노출
- 인식된 단어를 탭하면 저장 위치 선택 화면에서 태그를 골라 단어장에 저장 가능 (6.1 참조 — 카메라 인식은 코스 맥락이 없어 예외적으로 수동 태그 선택)
- "이 표현, 여행 회화 3과에서 배운 표현이에요" 같은 학습 연계 알림

### 5.3 기술 구현 방향
- 직접 OCR·음성인식 엔진 개발은 비현실적 (ML 전담 인력·수개월 이상 소요)
- 검증된 외부 API 연동으로 해결: Google Cloud Vision + Translate, 네이버 파파고 API 등
- 개발자 1명 기준 프로토타입 1~2주 내 가능한 수준

### 5.4 단계적 출시 계획
| 단계 | 범위 |
|---|---|
| MVP (Should) | 카메라 문구 인식 (OCR + 번역) |
| **Should (카메라 이후)** | **오프라인 촬영 → 나중에 처리 (5.5)** |
| v1.1 (Could) | 음성 통역 (짧은 문장) |
| v1.2+ | 실시간 대화 통역 |

### 5.5 오프라인 촬영 — "찍어두면 나중에 챙겨둘게요" (아이디어 기록)

> 상태: **아이디어 확정, 구현은 카메라(5.1) 이후.** 지금 만들지 않고 근거와 방향만 기록한다.

**배경 — 지금까지 다룬 "막힘"은 전부 앱 안의 것이었다**
강제 결제·광고·잠긴 급수는 모두 *우리가 만든 막힘*이라 우리가 없앨 수 있었다. 그런데 **여행지에서 데이터가 안 터지는 것은 앱 밖의 막힘**이다. 메인 페르소나(여행러 지은)가 일본에서 로밍 없이 다니는 것은 매우 현실적인 상황이고, 하필 **가장 단어를 저장하고 싶은 순간**(간판·메뉴판 앞)에 앱이 무력해진다.
→ *"학습 의지를 막지 않는다"*(1.3)를 앱 밖의 제약까지 확장하는 기능이다.

**캐릭터와의 연결**: 토모의 핵심 특질이 **"기억해 뒀어요"**(14.4)다. 오프라인 촬영은 말 그대로 **나중에 기억해서 챙겨주는 일**이라 성격과 정확히 겹친다.

**동작**
1. 오프라인 감지 시 안내 (문구는 토모 톤으로): *"지금은 연결이 안 되네요. 찍어두면, 나중에 제가 챙겨둘게요."*
2. 촬영 → **로컬에 대기열로 보관** (OCR은 미실행)
3. 온라인 복귀 시 **조용히 자동 OCR 처리** → 단어장 후보로 정리 (알림 없음 — 14.4 과묵한 톤)

**설계 시 지킬 것 4가지**
| # | 내용 |
|---|---|
| 1 | **문구는 시스템 메시지 톤이 아니라 토모 톤** — "데이터가 연결되어 있지 않습니다" ❌ |
| 2 | **찍고 끝이 아니라 나중에 자동 처리** — 사용자가 다시 챙길 필요 없음 |
| 3 | **매번 전면 안내 금지** — 여행 내내 오프라인일 수 있다. 첫 진입 1회만 제대로, 이후엔 가벼운 표시. 반복되는 안내는 그 자체가 방해(1.2) |
| 4 | 🔴 **"안 되는 것"이 아니라 "되는 것"을 알린다** — 오프라인에서도 단어장·오답노트·이미 받은 편지는 볼 수 있다. **막힌 걸 알리는 화면이 아니라 열려 있는 걸 알리는 화면**으로 뒤집는다 |

**선행 과제 → 해결됨**: 오프라인 범위는 5.6에서 정의함.

### 5.6 오프라인 범위 — 열람 · 촬영 · 미리받기 3분할 (2026-07-22 확정)

**해소한 모순**: 11장 Should의 *"오프라인 저장(구독자용)"* 과 12장 *"학습은 무료·구독 동일하게 방해 없이 제공"* 이 충돌했다. 원인은 **"열람"과 "저장(다운로드)"을 한 단어로 묶은 것**. 셋으로 나누면 충돌이 사라진다.

| 구분 | 무료 | 구독 | 성격 |
|---|---|---|---|
| **① 이미 내 기기에 있는 것 열람** | ✅ | ✅ | 오답노트·저장한 단어·받은 편지(PDF)·촬영본. **이미 다운로드된 것을 오프라인에서 보는 건 기능이 아니라 당연한 동작** — 안 되면 오히려 버그 |
| **② 오프라인 촬영해두기 (5.5)** | ✅ | ✅ | 앱 철학의 핵심. 여기서 막으면 5.5의 의미가 없다 |
| **③ 콘텐츠 미리 받기** | ❌ | ✅ | *"비행기에서 볼 레슨 미리 다운로드"*. **온라인에서 미리 받아두는 편의** → 돈 주고 사는 편의라 구독 혜택으로 적절 |

**핵심 구분**: ①은 *"내가 이미 가진 걸 오프라인에서도 본다"*(당연), ③은 *"온라인에서 미리 받아둔다"*(편의). 11장 Should의 "오프라인 저장(구독자용)"은 **③만** 가리키는 것으로 정정한다. → 무료 사용자도 ①②로 "지금 급한 것"은 다 해결되므로 12장 철학과 충돌하지 않는다.

**오프라인 진입 화면(신규 51번)**: 5.5의 4번 원칙("되는 것을 알린다")을 이 화면이 구현한다. *"막힌 걸 알리는 화면"*이 아니라 *"뭐가 되는지 알려주는 화면"*.
> 토모: "지금은 연결이 안 되네요. 그래도 이건 지금도 할 수 있어요."
> · 저장해둔 단어 다시 보기 · 오답노트 복습 · 받아둔 편지 열기 · 📷 찍어두기

## 6. 나만의 단어장 (통합 단어장 시스템)

### 6.1 구조 — 통합 저장 + 태그 필터링

앱 내 모든 학습 콘텐츠(JLPT 독해, 여행 회화, 비즈니스, 뉴스, 전래동화, 카메라 인식 결과)에서 저장한 단어가 **하나의 단어장**에 모이되, 각 단어에 **태그**가 부여되어 필터링 가능.

**기본 태그 (5개, 학습 코스와 동일)**: JLPT / 여행 회화 / 비즈니스 / 뉴스·시사 / 전래동화
**커스텀 태그 (신규)**: 사용자가 직접 이름을 정해 추가 가능 (예: "출장 필수표현", "헷갈리는 단어"). 기본 태그와 시각적으로 구분해 표시 (점선 테두리 등)

**태그 부여 방식은 저장 경로에 따라 다름**:
- 레슨 본문·퀴즈·오답노트에서 탭하여 저장 → 현재 학습 중인 코스로 **자동 태그** (7장 참조, 변경 없음)
- 카메라로 인식해 저장 → **저장 위치 선택 화면**에서 기본 태그 또는 커스텀 태그 중 **1개를 직접 선택**. 카메라는 코스 맥락이 없어 자동 태그가 애매하므로 예외적으로 사용자가 직접 고름. 새 커스텀 태그도 이 화면에서 바로 생성 가능
- 태그는 **단일 선택**만 허용 (복수 태그 미지원 — 필터 로직을 단순하게 유지)

**속성(메타데이터)과 태그의 구분**: 단일 태그 규칙을 지키기 위해, 코스 내부의 세부 분류는 태그가 아니라 **단어 속성**으로 저장한다. 예를 들어 JLPT 단어는 `JLPT` 태그 하나만 갖고, **급수(N5~N1)는 속성**으로 보관 → 단어장에서 `JLPT` 태그를 선택하면 급수 **하위 필터**가 나타난다. (`JLPT`+`N3` 두 태그를 붙이지 않음)

**재분류(태그 변경)**: 단어장에서 어떤 단어든 태그를 언제든 다른 태그로 바꿀 수 있음 (카메라 인식 단어에 한정하지 않고 전체 단어에 동일 적용). 저장 시점에 급하게 고른 태그가 나중에 맞지 않아도 부담 없이 수정 가능 — 저장 위치 선택 화면에도 "태그는 나중에 다시 바꿀 수 있어요" 안내 노출

### 6.2 채택 이유
- 완전 분리형(코스별 단어장 각각 존재): 카메라 인식 단어의 저장 위치가 애매해짐
- 완전 통합형(태그 없음): 시험 대비 등 목적별 복습이 어려워짐
- 카메라 인식만 예외적으로 수동 선택하게 한 이유: 나머지 경로는 코스 맥락이 이미 명확해 자동 태그가 정확하지만, 카메라는 코스와 무관하게 언제든 켤 수 있어 자동 추정이 부정확할 수 있음
- → 저장은 한 곳에, 조회는 태그 필터로 → 문제 동시 해결

### 6.3 활용 연계
- 단어장 PDF는 **태그 필터가 적용된 상태 그대로** 생성 가능 (예: "이번 주 여행 회화 단어만 PDF로")
- ⚠️ **우표와는 별개**: 나만의 단어장 전체 PDF도 다른 PDF와 마찬가지로 **무료 통합 월 5회 / 구독 무제한**으로 제한됨 (12.1 참조). 우표는 PDF를 소비하지 않는 컬렉션 재화다(12.2).

## 7. 단어 저장 인터랙션 (앱 전체 공통 패턴)

### 7.1 채택 방식 — 탭 → 뜻 팝업 → 저장 버튼

단어를 탭하면 뜻·읽는법이 담긴 팝업이 뜨고, 팝업 안에 "단어장에 저장" 버튼 배치. 뜻 확인(학습)과 저장(수집)을 한 번의 인터랙션으로 동시 해결.

**검토했던 대안과 기각 이유**:
- 원탭 즉시저장: 실수로 저장되기 쉽고, 뜻을 확인하지 않고 저장되어 학습 효과 낮음
- 롱프레스 저장: 발견성이 낮고 모바일에서 오작동이 잦음

**예외 — 학습 카드 내 ⭐별표 (원탭 저장 허용)**: 단어 학습 카드(단어·어휘 탭)에서는 별표 한 번으로 즉시 저장한다. 카드는 정답 보기·자가판정을 거치는 **학습 맥락이 구조적으로 전제**되므로, 위 기각 사유("뜻을 확인하지 않고 저장")가 적용되지 않기 때문. 별표는 토글이라 되돌리기도 쉬움.

### 7.2 자동 태그 규칙
저장 시점에 사용자가 보고 있던 화면의 코스을 자동으로 태그. 별도 선택 과정 없음.
- 학습 본문(JLPT 독해·전래동화·뉴스 기사)에서 저장 → 해당 코스 태그
- 카메라 인식 결과에서 저장 → "여행 회화" 태그 + 📷 표시

### 7.3 적용 범위
아래 모든 화면에 동일한 인터랙션 패턴 적용 (일관된 사용자 기대 형성):
- 학습 본문 (JLPT 독해, 전래동화, 뉴스 기사)
- 퀴즈 문제 및 오답노트
- 카메라 인식 결과 화면

## 8. 학습 루프 및 오늘의 학습 요약

### 8.1 학습 루프 구조 (전 코스 공통 골격)
오늘의 학습 시작 → 레슨 콘텐츠 학습(단어 탭 저장 가능) → 퀴즈 진행 → 정답/오답 분기(오답 시 오답노트 자동저장) → 우표 적립 → 오늘의 학습 요약 → 다음 레슨 또는 홈으로.

**코스 간 공통점/차이점**: 전체 골격은 5개 코스 모두 동일 — 퀵메뉴로 코스를 전환해도 같은 사용 흐름을 유지해 재학습 비용을 없앰. 다만 "레슨 콘텐츠 학습" 단계의 화면 형식은 콘텐츠 성격에 따라 내부적으로 갈림:
- **읽기형** (뉴스·시사, 전래동화): 긴 지문 읽기 → 문장 속 단어 탭 저장 → 지문 하단에서 **`[읽기 완료]`(회독 +1)** 또는 **`[이해 확인해보기]`(선택적 퀴즈)**. 퀴즈는 **강제가 아니라 선택** — 편안히 읽는 경험을 보장하되, 원하는 사용자에겐 오답노트 루프를 유지 (8.5 참조)
- **구문·어휘형** (여행 회화, 비즈니스): 상황별 표현 카드 → 바로 객관식·받아쓰기·짝맞추기 퀴즈
- **혼합형** (JLPT): 문자·어휘 단계는 구문·어휘형처럼, 독해 단계는 읽기형처럼 동작. **단어·어휘 / 문법 / 독해 / 청해 4탭 구조**이며, 급수×영역 구조라 "과(課)" 단위가 없음 → 루프 마지막의 "다음 레슨"은 JLPT에서 **"다음 세션"** 으로 표기 (상세는 `JLPT_플로우_검토.md`)

### 8.2 오늘의 학습 요약 화면
레슨 완료 시 한 화면에서 아래 3가지를 제공:
1. **오늘 배운 단어** — 탭하여 저장한 단어 목록
2. **오답노트에 추가됨** — 틀린 문제의 질문+정답 (후리가나 항상 포함, 8.4 참조)
3. **오늘의 조언** — 그날의 오답 패턴 기반 1줄 학습 조언 (규칙 기반으로 MVP 구현 가능, 예: 오답이 몰린 카테고리를 감지해 안내)

우표 진행바를 화면 상단에 상시 노출 — **다음 편지까지 남은 우표 수**를 보여준다(예: "다음 편지까지 N장", 마일스톤 = 첫 편지 3장·이후 14장, 12.2 참조). **PDF 다운로드는 우표와 무관**하며 무료 통합 월 5회 한도로 언제든 가능하다(12.1). 즉 진행바는 "결제 게이지"가 아니라 **편지를 향한 컬렉션 게이지**다.

**코스별 추가 표시**: 코스 특성에 맞는 정보를 화면에 덧붙일 수 있음 (예: JLPT는 회독·진행률 변화, D-day).

#### 8.2.1 PDF 내보내기 콘텐츠 원칙 (전 PDF 공통) ⭐
**화면에 표시하는 항목과 PDF에 담는 항목은 다르다.** 사용자가 PDF로 받는 것은 "다시 볼 학습 내용"이지, 앱 화면 상태가 아니다.
- **PDF 포함**: 오늘 배운 단어 · 오답노트 추가분 · 오늘의 조언 등 **학습 자료로서 가치가 있는 내용만**
- **PDF 제외**: 진행률·회독 수·D-day·우표 진행바 등 **앱 내 상태·게임화 요소** — 종이에서는 의미가 없고, 인쇄 시점 값이 박제되어 오히려 혼란을 준다
- 이 원칙은 요약 PDF뿐 아니라 **오답노트·단어장·장문 독해 PDF 전부에 동일 적용**한다.

### 8.3 학습 기록 (MY 탭 신규 메뉴) — 브랜드 표기 "**편지함**"
날짜별로 받은 **토모의 편지**를 모아보는 화면(브랜드 표기 "편지함"). MY 탭 안에 신설하며, 항목을 탭하면 그 편지가 열린다(일본어 본문 + 후리가나·해석 토글). 성장 기록·재방문 동기로 작용한다.
> **v2.9**: 편지함은 「토모의 편지 컬렉션」이다(옛 「일별 요약 모아보기」에서 재정의). 일별 세션 요약은 세션 종료 화면·요약 PDF로 남고 편지함엔 넣지 않는다. 편지함엔 **받은 편지만** 모은다(쪽지·요약 PDF는 성격이 달라 별도).

### 8.4 읽기 도움 토글 — **후리가나 / 한글 발음 개별 토글** (2026-07-20 개정)

**개정 이력**: 당초 후리가나와 한글 발음을 **하나의 토글로 묶었다**("두 정보가 필요한 사용자군이 대부분 겹친다"). 그러나 이는 **정적인 관점**이었고, 학습이 진행되면 둘은 갈라진다는 점을 놓쳤다. → **개별 토글 2개로 분리**한다.

**분리 근거 — 두 도구의 수명이 다르다**
| | 후리가나 | 한글 발음 |
|---|---|---|
| 성격 | **오래 쓰는 도구** (N2까지도 필요) | **빨리 떼야 하는 보조바퀴** (초반 몇 주) |
| 부작용 | 없음 | 🔴 **일본어 발음을 왜곡** — `つ` `ざ` `ん` 등은 한글로 정확히 표기 불가. 계속 의존하면 틀린 발음이 굳는다 |

묶어 두면 **한글 발음을 떼려는 순간 후리가나까지 사라져**, 초급을 벗어나는 사용자에게 잘못된 선택을 강요하게 된다.

**기본값 — 온보딩 Q2(현재 수준) 연동**
| Q2 응답 | 후리가나 | 한글 발음 |
|---|---|---|
| 완전 초보 | ON | **ON** |
| 조금 안다 이상 | ON | **OFF** |
→ 별도 질문 없이 첫 화면부터 수준에 맞게 노출된다(10.2의 진단 데이터 재사용).

**레이아웃 처리 — 둘을 다르게 다룬다**
| | 처리 | 이유 |
|---|---|---|
| **후리가나** | **공간 항상 확보**(표시 여부만 전환) | 읽는 중 **자주** 켰다 껐다 한다(모르는 한자를 만날 때마다). 점프하면 읽기가 끊긴다 |
| **한글 발음** | ~~공간 회수(`display:none`)~~ → 🔄 **공간 항상 확보 + opacity 전환** (2026-07-28 3차) | 아래 개정 참조 |

> **토글 빈도가 다르므로 처리가 달라도 된다.** 레이아웃 점프 방지는 "자주 토글하는 것"에만 필요하다.
> 🔄 **개정(2026-07-28 3차) — 한글 발음도 공간을 항상 확보한다(후리가나와 동일 처리).** 당초 한글 발음은 *"한 번 끄면 계속 끈다 → 사실상 설정"* 이라 공간 회수(빈 줄 절약)가 맞았다. 그러나 **읽기 도움 3차 개정으로 발음이 카드마다 OFF에서 시작**하게 되면서, 발음은 더 이상 "한 번 끄는 설정"이 아니라 **카드마다 사용자가 켰다 끄는 자주 토글하는 컨트롤**이 됐다. → 위 원칙("자주 토글하는 것만 점프 방지 필요")을 **그대로 적용하면** 이제 발음도 점프 방지 대상이다. 대표님 지적(*"발음 나올 때 너무 많이 움직인다"*)이 이 논리와 일치. 구현 = 표제어·예문 발음 줄을 **항상 렌더 + `opacity` 전환**(브라우저 검증: 발음 토글 시 표제어·하단 버튼 이동 **0px**). ⚠️ 대가: 발음을 안 쓰는 카드에도 한 줄 높이가 늘 잡힌다(빈 줄 절약을 점프 방지와 맞바꿈 — 3차의 "자주 토글" 성격상 점프 방지 우선).

- **오답노트도 동일 규칙**: 별도 예외를 두지 않는다("몰랐던 것을 다시 보는" 공간이므로 읽기 지원이 기본으로 필요하다는 원칙은 유지되며, Q2 연동 기본값이 이를 충족).
- **적용 범위 — 통합 원칙 (2026-07-20 확정)**:
  > **"먼저 스스로 부딪히는 면(문제면·원문면)에서는 읽기 도움이 기본 꺼짐. 도움은 사용자가 켠다."**
  - **기본 OFF (스스로 부딪히는 면)**: ① 학습 카드 **앞면**(떠올리는 순간) ② 읽기형 **지문 첫 노출**(원문에 부딪히는 순간)
  - **~~기본 ON (그 외 전부)~~ → 「사용자 설정을 따른다」 (그 외 전부)**: 정답면·단어목록·오답노트·PDF 등은 **강제 ON이 아니라 사용자의 읽기 도움 설정**(MY › 설정, 온보딩 Q2로 초기화)을 따른다. 각 화면에 즉석 토글이 있어 언제든 바꾼다.
  - 🔄 **개정(2026-07-28) — 학습 카드 「정답면(뜻 보기)」은 기본 ON에서 빠진다.** 후리가나·한글발음·뜻보기를 **완전 독립 토글**로 한다. **뒤집는 이유**: 종전 규칙은 "정답면=위로받는 자리라 도움을 켜 준다"였으나, 실제 구현은 *뜻 보기를 누를 때마다 후리가나·발음을 강제로 켜서 사용자가 끈 상태까지 덮어썼다.* 대표님 판단 — **사용자가 원하지도 않은 보조(후리가나·발음)를 뜻 보기라는 다른 동작에 얹어 강제하는 것은 도움이 아니라 참견**이다. 뜻 보기는 뜻·예문만 연다. 후리가나·발음은 사용자가 켠 그대로 유지된다(앞면 기본 OFF 규칙은 그대로 — 새 카드는 셋 다 OFF에서 시작). ⚠️ **(2차 개정, 같은 날 2026-07-28) 이 결정을 앱 전체로 확장한다** — 단어목록·오답노트·PDF도 "기본 ON 강제"를 폐기하고 **사용자 설정을 따른다**(대표님 판단: *"사용자가 선택할 수 있게 하는 게 낫다"*). **뒤집는 이유**: 어느 화면이든 사용자 뜻과 무관하게 보조를 강제로 켜 두면, 이미 뗀 사용자에겐 참견이고 한글 발음의 경우 **틀린 발음이 굳는 부작용**(8.4 표)까지 방치하게 된다. → 규칙이 「부딪히는 면=OFF, 그 외=사용자 설정」 두 갈래로 단순해진다.
  - 예외를 개별로 쌓지 않고 위 한 문장으로 판단한다. 앞으로 유사 상황도 이 원칙으로 결정.
  - **부딪히는 면(앞면·지문 첫 노출)만** MY › 설정과 무관하게 항상 OFF에서 시작한다(설정이 ON이어도). 그 외 모든 면은 위처럼 **사용자 설정을 따른다.**
  - 🔄 **(3차 확정, 2026-07-28) 「사용자 설정을 따름」의 적용면을 못박는다 — 학습 카드 정답면은 제외.** 2차가 "그 외 전부=사용자 설정을 따름"이라 했으나, 이를 **학습 카드의 정답면(뜻 보기)에까지 적용하면** 설정 ON 사용자에겐 *"뜻 보기가 후리가나·발음을 강제로 켜는 것"* 과 구분되지 않아 **2차의 취지(강제 배제)가 스스로 깨진다**(대표님이 실제 그렇게 체감). → **학습 카드(단어 등 *부딪히는* 콘텐츠)의 정답면은 설정을 자동 적용하지 않는다**: 후리가나·발음·뜻보기는 **완전 독립**, 후리가나·발음은 카드 안 토글로만 켜지고 새 카드마다 OFF에서 시작. **「사용자 설정을 따름」은 *부딪히지 않는* 열람면**(단어목록·오답노트·PDF 등 "고르는/다시 보는" 화면)에만 적용한다. 구현·브라우저 검증 = `기획/진행상태.md` 2026-07-28 (3차).
- **해석 — 토글이 아니라 "문장 탭"** (2026-07-21 확정):
  - 후리가나는 읽기를 *돕는* 것이지만 **해석은 읽기를 *대신하는*** 것이다. 전체를 켜는 토글로 두면 일본어를 건너뛰고 해석만 읽게 된다(대역 텍스트의 알려진 함정).
  - 따라서 해석은 **문장 끝의 작은 아이콘 `⋯`을 탭했을 때 그 문장만** 표시한다. → **막힌 곳만** 여는 구조라 의존이 원천적으로 줄어든다.
  - **인터랙션 규칙 통일**: `단어 탭 → 뜻 팝업`(7.1)과 `문장 탭 → 해석`이 같은 원리다. *"모르면 탭한다"* 하나로 기억된다.
  - 단어 탭과 충돌하지 않도록 **문장 끝 아이콘만** 탭 대상으로 한다. 롱프레스는 쓰지 않는다(7.1에서 발견성·오작동 사유로 기각).
  - 다 읽고 대조하려는 니즈를 위해 **지문 하단에 작은 텍스트 링크 `전체 해석 보기`** 를 둔다(상단 토글이 아니라 하단 보조 액션이라 읽는 중엔 눈에 들어오지 않음).
  - → 결과적으로 **읽기형 지문의 상단 토글도 `후리가나`·`발음` 2개**로, 앱 전체가 동일해진다.
- **화면별 빠른 토글**: 단어 목록·레슨 본문·오답노트 등 각 화면 상단에서 그때그때 on/off 가능. 개별 분리에 따라 **토글이 2개**가 된다(`후리가나` / `발음`). **읽기형 지문도 동일하게 2개** — 해석은 토글이 아니라 문장 탭이므로(위 참조) 앱 전체가 같은 구성이다.
- **MY › 설정 기본값**(35번 "설정 — 화면 표시"): 레슨·단어장·오답노트·PDF에 공통 적용되는 기본 상태. **후리가나 / 한글 발음 각각** 설정하며 초기값은 위 Q2 연동 규칙을 따른다.
- **PDF 저장 규칙**: 다운로드 시점의 토글 상태를 그대로 캡처. 이후 설정을 바꿔도 이미 받은 PDF는 그대로 유지됨. 후리가나 없이 깔끔하게 학습하고 싶은 사용자는 토글을 꺼서 PDF에도 반영 가능

### 8.6 오답 피드백 — **`O`/`X` 기호를 쓰지 않는다** (2026-07-22 확정)

**배경**: 17번 피드백 화면 상단의 `✕` 아이콘이 *"너무 별로다"* 는 지적. 타당하다 — **`O`/`X`는 채점의 기호**이고, 우리는 채점하는 앱이 아니다(1.3).

**확정 — 등불은 심판하지 않는다. 비춘다.**
| 결과 | 표현 |
|---|---|
| **오답** | 토모가 **정답 쪽을 비추는** 구도. 문구는 *"여기를 볼까요"* 톤 |
| **정답** | 토모가 **조용히 한 번 반짝**(250ms 이내, 1회) |

> 이는 14.2의 **"캐릭터는 하나, 비추는 대상만 변화"** 와 정확히 맞물린다. 소품이 바뀌듯 **비추는 대상**이 바뀐다.

**🔴 반드시 지킬 3가지**
| # | 규칙 | 이유 |
|---|---|---|
| 1 | **판정은 문구가 명시적으로 나른다** | 기호를 없앤다고 **정오 정보까지 없애면 학습이 불가능**하다. "맞았어요" / "아쉬워요, 정답은 ~" 를 텍스트로 반드시 표기 |
| 2 | 🔴 **색·밝기만으로 구분하지 않는다** | WCAG 1.4.1. 색각 이상 사용자와 미묘한 밝기를 못 읽는 환경을 배제하게 된다 |
| 3 | 🔴 **오답이라고 토모를 어둡게 하지 않는다** | 토모의 밝기는 **학습 상태** 신호다(14.2). 틀렸다고 어두워지면 *"네 잘못"* 으로 읽힌다 — 오프라인 화면에서 내린 것과 **같은 판단**(5.6) |

**⚠️ 적용 범위 — 17번 피드백 화면에 한정한다.**
**47번 오답노트 모아보기의 `✕`(틀림) / `⤼`(넘어감) 구분은 유지**한다. 거기는 **목록**이라 훑어보기용 기호가 필요하고, *"틀림과 넘어감은 성격이 다르다"* 는 별개 결정이다(JLPT 검토 ⑦-3). **감정을 다루는 면**과 **분류를 다루는 면**은 다르게 취급한다.

### 8.7 읽기형 목록 — **인지 보조** (2026-07-22 확정)

**문제**: 뉴스·시사 목록이 **일본어 제목만** 노출된다. N5~N4 학습자는 **무엇에 관한 기사인지 알 수 없어 고를 수가 없다.** 학습 이전에 **선택**이 막힌다.

**확정 — 3가지를 함께 쓴다**
| # | 수단 | 내용 |
|---|---|---|
| 1 | **한국어 주제 라벨** (1줄) | 제목 **번역이 아니라 주제** — `엔화 환율` · `지진 대비 훈련`. 인지 문제를 가장 직접 해결 |
| 2 | **카테고리 픽토그램** | 정치 / 경제 / 사회 / 스포츠 / 날씨 / 문화. 저작권·오해 위험 **0** |
| 3 | **카드형 ↔ 리스트형 전환** | 카드형=탐색(픽토그램·주제 크게) / 리스트형=조밀(아는 걸 빨리 찾기). **Should** |

**🔴 실제 뉴스 사진은 쓰지 않는다 — 저작권보다 「오해」가 더 큰 이유**
- 원본 사진 사용은 명백한 침해라 애초에 불가.
- **무료 이미지로 대체하는 것도 채택하지 않는다.** 뉴스는 **사실 보도**라, 내용과 비슷한 사진을 붙이면 사용자는 **그 사건의 사진으로 읽는다.** 학습 앱이 **오보의 통로**가 되어선 안 된다.
- → 사진 대신 **픽토그램**. 분류 정보만 전달하고 사실을 주장하지 않는다.
- ⚠️ 예외 검토 여지: NHK Web Easy 등이 **명시적 재사용 허가·API**를 제공하면 별개 사안 → 슈슈 확인 과제.

**"목록에 한국어를 넣는 건 해석 의존 아닌가?"** — 아니다.
> **목록은 「고르는」 화면이지 「읽는」 화면이 아니다.** 8.4가 해석을 문장 탭으로 뺀 것은 *지문을 읽는 중* 해석에 기대는 것을 막기 위함이다. **무엇을 읽을지 고르는 단계에서 내용을 모르게 두는 것은 도움이 아니라 방해**다.

**전래동화**: 같은 목록 UI를 쓰되 **삽화 이미지 슬롯이 유효**하다 — 직접 제작 또는 퍼블릭 도메인이라 저작권이 깨끗하고, **이야기라 사실 오해의 소지가 없다.**

## 10. 온보딩 진단 테스트 및 개인화

### 10.0 전체 온보딩 화면 순서
스플래시 → **앱 소개 (신규)** → 회원가입·로그인 → 진단 테스트(10.2) → 추천 결과(10.3) → 레벨 테스트 → 첫 학습 시작

**앱 소개 화면 추가 배경**: 스플래시 직후 바로 회원가입을 요구하면 "이 앱이 뭔지도 모르는데 가입부터 하라니" 하는 이탈 요인이 됨. 1~2장 분량으로 핵심 가치만 압축 전달 후 하단에 가입 버튼 배치.
- 1장: "목적에 맞는 일본어 학습" — 코스별 커리큘럼 소개
- 2장: "강제 결제 없이, 원하는 만큼" — 핵심 철학(2장) 전달

### 10.1 배경 — 왜 "완전 제한형"이 아닌가
당초 "선택한 커리큘럼만 볼 수 있게" 하는 구조를 검토했으나, 설문 Q2 재분석 결과 응답자의 55%(11/20명)가 학습 목적을 2개 이상 복수 선택한 것으로 확인됨. 커리큘럼 접근을 완전히 하나로 제한하면 과반의 사용자에게 불편을 줄 수 있어, "메인 코스 집중 + 서브 코스 제안 + 언제든 전환" 구조로 설계 방향을 조정함.

### 10.2 온보딩 진단 테스트 — 4문항 (약 40초)

시험(정답 판별)이 아닌 진단(취향·상황 파악) 형태. 각 문항이 특정 기능과 1:1로 연결되어, 짧은 문항 수로도 개인화 효과를 확보.

| 문항 | 목적 | 결정되는 것 |
|---|---|---|
| Q1. 일본어가 가장 급하게 필요한 순간은? | 목적 파악 (가중치 50%) | 메인 코스 추천 |
| Q2. 지금 일본어를 얼마나 알고 있나요? | 현재 수준 파악 | 시작 난이도 (정식 레벨 테스트로 이후 정교화) |
| Q3. 하루에 학습에 쓸 수 있는 시간은? | 학습 강도 파악 | 오늘의 학습 분량, 푸시 알림 빈도 |
| Q4. 학습할 때 나를 움직이게 하는 것은? | 동기 유형 파악 | 홈 화면 위젯 노출 순서 (10.4 참조) |

Q1 옵션 예시: 여행(✈️) / 시험(📝) / 업무(💼) / 문화·뉴스(🎌) → 각각 여행회화/JLPT/비즈니스/전래동화·뉴스로 매핑
Q3는 설문 이탈원인 1위("바빠서" 35%, Q6)에 대응하는 문항 — 시간이 부족하다고 답한 사용자에게는 짧은 세션 위주로 설계해 부담을 사전에 줄임

### 10.3 추천 결과 화면 — 메인 + 서브 제안
- 메인 코스 1개를 크게 추천 (Q1 응답 기반)
- 함께 볼만한 서브 코스을 작게 함께 제안 (복수 목적 사용자 대응)
- 홈 화면은 메인 코스 콘텐츠 중심으로 구성되어 첫 화면이 복잡하지 않음 ("숨김"이 아닌 "기본값 집중")

### 10.4 코스 전환 — 퀵메뉴
- 홈 화면 상단/하단에 코스 전환 아이콘 상시 노출
- 탭 한 번으로 다른 코스(JLPT/여행회화/비즈니스/뉴스·시사/전래동화)으로 즉시 전환 가능
- "언제든 바꿀 수 있다"는 점을 온보딩 완료 화면에서 명시적으로 안내

### 10.5 홈 화면 개인화 — 위젯 순서 조정 (레이아웃 자체는 단일)
Q4(동기 유형) 응답에 따라 완전히 다른 레이아웃을 만들지 않고, **동일한 홈 화면 구조 내에서 위젯(스트릭/진도율/우표) 노출 순서만 재배열**하는 경량 방식으로 채택.

| Q4 응답 | 상단 배치 위젯 | 심리적 근거 |
|---|---|---|
| 연속 기록이 끊기지 않는 것 | 스트릭 위젯 | 손실 회피(Loss Aversion) |
| 목표에 가까워지는 것 | 진도율 위젯 | 목표 근접 효과(Goal Gradient Effect) |
| 보상을 모으는 재미 | 우표 위젯 | 가변적 보상(Variable Reward) |

**채택 이유**: 완전히 다른 3개 레이아웃 설계·개발·테스트는 MVP 단계에서 비용 대비 효과가 낮고, "동기 유형"이 실제 재방문율에 미치는 영향은 아직 설문으로 검증되지 않은 가설임. 위젯 노출 요소는 동일하게 유지하고 배치 순서만 개인화하여, 낮은 구현 비용으로 유사한 효과를 노림. 런칭 후 A/B 테스트로 효과 검증 예정 (미검증 가설로 리스크 항목에 별도 기재).

## 11. 기능 범위 (Scope) — MoSCoW

### 11.0 스코프 원칙 — **기능은 5개 코스 / 콘텐츠는 3개 먼저** (2026-07-22 확정)

스코프를 정리하며 세 가지를 결정했다: ① MVP에 코스 5개 전부 ② 스피킹 퀴즈 Must ③ 결과물(PDF) 4종 전부 Must. 이는 사실상 **"기능 스코프는 줄이지 않는다"** 는 결정이다. 그렇다면 출시가 밀리지 않게 하는 방법은 **"줄이기"가 아니라 "순서"** 뿐이다.

**핵심 통찰 — 무거운 것은 기능이 아니라 콘텐츠다.**
- **기능**(퀴즈 6종·PDF 4종·회독 모델 등)은 한 번 만들면 **5개 코스가 공유**한다. 설계도 끝났다. → **5개 코스 전부 지원하게 만든다(그릇을 다 만든다).**
- **콘텐츠**(JLPT 문항·청해 음성·3단 해설·전래동화 리라이트…)는 코스마다 따로 채워야 하고 제작비가 크다. → **3개 코스부터 채운다(비즈니스·JLPT·여행회화).**

| | MVP 출시 시 |
|---|---|
| **기능** | 5개 코스 전부 지원 |
| **콘텐츠** | 비즈니스 · JLPT · 여행회화 **3개만 채움** |
| 뉴스·시사 / 전래동화 | 앱에 **코스는 존재**하되 "곧 열려요" 상태, 출시 후 순차 확충 |

**왜 이 3개인가 (근거)**
- 설문 관심 코스 1위가 **비즈니스·JLPT 공동 30%**, 여행회화는 최대 수요(Q2 90%). → 수요 순서와 일치 (13장 2번).
- **뉴스·시사**는 시의성 콘텐츠라 어차피 출시 후에도 계속 채워야 함 → 처음부터 꽉 채울 이유가 없다.
- **전래동화**는 자체 리라이트가 승인 대기 중이라 어차피 시간이 걸린다 (`리서치/01_전래동화` 결정 4).

→ 대표님 요구("5개 다 넣는다")를 지키면서(앱엔 5개 코스가 다 있음), 출시는 3개 코스 콘텐츠로 현실적 시점에 한다.

## 12. 수익 모델

| 단계 | 기간 | 제공 내용 |
|---|---|---|
| 1. 프리미엄 체험 | D1~D7 | 광고 없음, 전체 콘텐츠 잠금 해제, PDF 다운로드 무제한 |
| 2. 무료 플랜 | D8~ | 전체 콘텐츠 계속 이용 가능(제한 없음) + 배너 광고. 학습 흐름 자체에는 어떤 대기·제한도 없음 |
| 3. 구독 플랜 | 월 1,900원 / 연 20,900원 | 광고 제거 + PDF/내보내기 대폭 확대 (아래 표 참조) |

**설계 원칙 변경**: 당초 검토했던 "레슨 간 3초 대기 + 복습카드"는 채택하지 않음. 레슨마다 반복되는 마찰은 설문 이탈 1위 원인("바빠서·귀찮아서" 35%)을 오히려 자극할 수 있다고 판단해 제외. 대신 **마찰 지점을 학습 흐름 밖, PDF/내보내기 시점 하나로 단순화**함 — 학습 자체는 무료·구독 사용자 모두 동일하게 방해 없이 제공하고, "결과물을 가져가는" 순간에만 구독 여부에 따른 차이를 둠.

### 12.1 PDF/내보내기 할당량 비교

> **⭐ v2.8 개정**: PDF는 **우표와 완전히 분리**됐다. 우표로 PDF를 사는 규칙(옛 7/5/10)은 폐지하고,
> **모든 PDF를 종류 무관 통합 월 5회**로 통일한다. 우표는 이제 편지를 모으는 컬렉션 재화일 뿐이다(12.2).

| 항목 | 무료 플랜 | 구독 플랜 |
|---|---|---|
| **전체 PDF (요약·오답노트·단어장·독해 합산)** | **월 5회 통합** (매월 1일 리셋) | **무제한** |
| 배너 광고 | 노출 | 제거 |

- **통합 단일 규칙**: 종류별 쿼터(옛 모델)는 설명이 복잡하고 구독 유인이 약해 폐기. "이달 PDF 5번"
  한 문장으로 이해된다. 헤비 유저는 자연스럽게 구독으로 유도된다.
- **무료 사용자 제한 원칙**: 완전 차단이 아닌 "기회는 주되 약간의 불편함" — 콘텐츠 열람·학습 자체는
  언제나 무제한, **결과물을 소장하는 PDF 다운로드에만** 상한을 둔다. 월 5회는 라이트 유저의 실사용을
  대부분 커버해 불쾌한 차단이 되지 않는다.

### 12.2 우표 시스템 — 컬렉션 모델 (v2.8 재작성)

> **은유의 뼈대**: **우표를 모으면 편지가 온다.** 하루의 학습이 쌓여 편지 한 통이 되는 구조 — "왜 이걸
> 모으면 저게 오는가"가 은유로 완결된다. (구 쿠키 체계는 이 연결이 없어 그냥 포인트로 느껴졌음 — 14.1 참조)
>
> **⭐ v2.8 — 소비형 → 컬렉션형 전환.** 우표를 "써서" PDF를 사던 옛 모델(7/5/10)을 폐기했다. 이유:
> ①우표를 소비처와 묶으면 결국 **게임 재화·포인트 상점**이 되어 "밝혀주되 끌지 않는다"(1.3) 철학과 멀어진다.
> ②PDF는 결과물 소장 기능일 뿐이라 **수익 축(구독)**에 두는 게 맞고, 우표/편지는 **몰입 리워드 축**으로
> 분리하는 편이 은유도 깨끗하다. → **우표는 소비하지 않고 계속 쌓이며, 편지는 그 이정표로 도착한다.**

**적립**: "오늘의 학습" 1단위 완료당 **우표 1장** (모듈 단위 아님). 우표는 소비되지 않고 **영구 누적**된다.

**편지 마일스톤 (핵심 수치)**
| 항목 | 값 | 근거 |
|---|---|---|
| 편지 1통에 필요한 우표 | **14장** (약 2주 = 월 2통) | 편지는 유틸이 아니라 감성 리워드 — 너무 흔하면 감동이 옅고 너무 멀면 동기가 끊긴다. 2주 간격이 희소성·동기의 균형점 |
| **첫 편지 (온보딩 가속)** | **3장** | 신규 사용자가 3일 안에 첫 편지를 받아 초반 성취·리텐션 확보. 두 번째 편지부터 14장 균일 |

- 예시 누적: 3장→1통, 17장→2통, 31장→3통 …
- **편지 ≠ PDF**: 편지는 토모가 보내는 감성 콘텐츠(문안·발송 화면 설계는 후속). 요약/오답노트/단어장/독해
  **PDF는 우표와 무관**(12.1의 월 5회로 별도 관리). 학습 기록 모아보기는 **"편지함"**(8.3).
- **유료 구매 불가** (11장 Won't) — 우표는 학습 보상으로만 획득.

**구독과의 관계**: 구독 가치 = **기능**(광고 제거 + PDF 무제한). 옛 모델의 **우표 350장 대량 증정은 폐지**한다
— 우표를 소비하지 않으므로 대량 증정은 의미가 없고, 구독이 몰입 리워드(우표/편지)까지 사면 "돈으로 성취를
산다"는 인상을 줘 철학과 충돌한다. **구독은 편의를 사는 것이지 편지를 사는 것이 아니다.**

**설계 제약**: 우표·편지는 **학습 콘텐츠·기능을 여는 열쇠로 절대 쓰지 않는다**(1.3 철학, 11장 Won't).
**검토 후 기각한 방향**: 우표 소비 상점(위 전환 이유), 캐릭터 소품·의상 커스터마이징(14.2 위배), 스트릭
프리즈(손실회피 자극 → 재촉 철학과 충돌), 구독 전용 기능 해금(구독 가치 훼손).

## 14. 브랜드 캐릭터 컨셉

### 14.0 브랜드 정체성 — 토모리(トモリ)와 토모(とも)

| 항목 | 내용 |
|---|---|
| **서비스명** | **토모리 (トモリ / Tomori)** |
| **캐릭터명** | **토모 (とも)** |
| **캐릭터 정체** | **작은 등불** |
| **리워드 재화** | **우표(切手)** → 모으면 **편지**가 온다 |

**이름의 이중 의미 (브랜드의 핵심)**
`とも`는 일본어에서 두 가지를 동시에 뜻한다.
- **友(とも) = 친구**
- **灯す(ともす, 불을 켜다)의 어간**
→ 즉 **"친구이자 불빛"**. 서비스명 `トモリ(灯り·ともり)`는 실제로 *"불이 켜짐"* 이라는 뜻이면서, **"토모와 함께"** 로도 읽힌다. 이름 하나에 제품의 정체가 전부 들어있다.

**세계관**
> 토모는 작은 등불이다. 누군가 배우려 할 때 조용히 켜지고, **그 사람이 떠나도 꺼지지 않는다.**
> 토모는 길을 대신 걷지 않는다. 다만 앞이 조금 보이게 해줄 뿐이다.
> 하루의 학습이 끝나면 토모는 **우표 한 장**을 건넨다. 우표가 모이면 **편지**가 온다 — 오늘 배운 것들이 담긴 편지.

**철학과의 결합**: "밝혀주되 끌지 않는다"가 곧 *학습 의지를 막지 않는다*(1.3)의 시각적 번역이다. 등불은 소리치지 않고 빛으로만 존재하므로, **방해 요소를 최소화한다**는 제품 정신과 상징이 일치한다.

### 14.1 컨셉 변경 이력
1. **초기 — "말랑말랑 우표 반죽 요정"**: 코스별 캐릭터 5명(반죽) → 완성된 우표로 성장하는 세계관. 두 가지 문제로 기각.
   - **코스별 캐릭터 분리**는 "퀵메뉴로 언제든 코스를 자유롭게 전환한다"는 제품 철학과 충돌. 제작 비용도 5배.
   - **반죽→완성으로 성장하는 서사**는 "학습에 끝이 있다"를 암시 — 끝없이 학습을 이어가는 앱 철학과 정면 배치.
2. **중간 — 단일 고정 캐릭터 "토모" + 리워드 우표**: 성장 서사는 제거했으나 세 가지 공백이 남아 재검토.
   - **"토모가 무엇인지" 정체가 정의되지 않음** — 성장 서사를 걷어내자 정체성도 함께 사라져 디자이너가 그릴 수 없는 상태가 됨.
   - **우표는 일본어와 무관** — 5개 코스가 전부 일본인데 보상만 서양 과자라 세계관에 일본적 정서가 없음.
   - **"우표 7개 → PDF"의 논리가 없음** — 리워드와 사용처가 은유로 연결되지 않아 그냥 포인트로 느껴짐.
3. **현재 — 토모리(등불) + 우표·편지 (2026-07-20 확정)**: 위 세 공백을 모두 해소.
   - 정체 = 등불(명확), 일본 정서 = 초롱·편지(연결), 리워드 논리 = **우표를 모으면 편지가 온다**(완결).

### 14.2 확정 컨셉 — 캐릭터는 하나, **비추는 대상**만 변화

**토모는 단일 고정 캐릭터**다. 성장하거나 완성되지 않고, 코스와 무관하게 항상 동일한 모습으로 함께한다 — "학습에 끝이 없다"는 철학을 캐릭터 자체가 체현.

**상황별 표현은 "드는 것"이 아니라 "비추는 것"으로 처리한다.**
등불의 본질은 *비춤*이므로, 소품을 손에 쥐는 대신 **토모가 비추는 대상**이 바뀐다. 이 규칙 덕분에 "캐릭터는 하나 고정"이 더 자연스럽게 성립한다. (사용자 커스터마이징 아님 — 앱이 문맥에 맞춰 자동 노출)

| 상황 | 토모가 비추는 것 |
|---|---|
| 여행 회화 | 캐리어 |
| 비즈니스 | 서류가방 |
| JLPT | 연필 |
| 뉴스·시사 | 신문 |
| 전래동화 | 책 |
| 오답노트·복습 | 안경 (또는 틀린 자리를 낮게 비춤) |
| 재접속 인사 | 반짝 밝아지며 맞이함 |

**밝기·흔들림이 곧 표정이다** (등불 고유의 표현 언어)
과묵한 관찰자 톤(14.4)이라 표정 진폭이 작아야 하는데, 등불은 **밝기로 감정을 전달**할 수 있다.
- 기본: 은은하게 켜짐 / 재접속: 반짝 밝아짐 / 오답·복습: 차분히 아래를 비춤 / 복귀: **그대로 켜져 있음**

**코스 구분은 캐릭터가 아니라 컬러·태그 시스템으로** 처리한다(코스 카드 색상, 단어장 태그 색상).

**캐릭터의 역할**: 코스를 구분하는 장치가 아니라 앱 전체를 관통하는 조용한 동반자. 동일한 토모가 일관된 톤으로 등장한다. 단, **학습 중에는 등장하지 않는다**(흐름 방해 금지, 1.2).

#### 14.2.1 🆕 등장 조건 — 어디에 나오고 어디에 안 나오는가 (2026-07-23 확정)

*"학습 중에는 등장하지 않는다"* 와 8.6의 *"오답이면 토모가 비춘다"* 가 충돌하는 것처럼 읽혀 규칙으로 정리한다.

> **판별 기준 한 줄: 판단하거나 집중하는 순간엔 없고, 결과를 마주하거나 쉬는 순간엔 있다.**

**❌ 등장하지 않는다 — 사용자가 「하는 중」**
| 화면 | 이유 |
|---|---|
| 14 학습 카드 **앞면** | 뜻을 떠올리는 중. 시선을 뺏으면 안 된다 |
| 16 퀴즈 **푸는 중** | 집중 |
| 12·48·49 지문·문서·대화 **읽는 중** | 읽기가 끊긴다 |
| 22~26 단어장 · 35~39 설정 | 도구 화면. 감정이 낄 자리가 아니다 |
| 🔴 **40~44 구독·결제 전 구간** | **아래 별도 규칙** |

**✅ 등장한다 — 사용자가 「마주하는」 순간**
| 화면 | 역할 |
|---|---|
| 8 홈 | 밝기로 학습 상태 |
| **17 정답·오답 피드백** | 오답이면 **정답 쪽을 비춤**(8.6). 판단이 **끝난 뒤**다 |
| 19 우표 적립 · 20·21 오늘의 편지 | 결과를 받는 순간 |
| 50 토모의 쪽지 | 토모 본인의 화면 |
| 51 오프라인 진입 | *"되는 것"* 을 알리는 순간 |
| 34 MY 홈(프로필) | 쉬는 화면 |
| **5 추천 결과** · **7 첫 학습 시작** | 진단 결과를 마주하는 순간 · 첫 인사 |
| **47 오답노트 모아보기** | 14.2 표에 이미 *"틀린 자리를 낮게 비춤"* 이 있다 |
| **빈 상태 화면**(단어장·편지함·오답노트가 비었을 때) | 안내가 필요한 순간. 빈 화면에 사람이 없으면 버려진 느낌이 든다 |

**등장할 때 지킬 조건 2가지**
1. **말 걸지 않는다** — 문구는 화면이 나르고 토모는 **비추기만** 한다
2. **세로 공간을 추가로 쓰지 않는다** — 토모 때문에 해설이 밀려나면 안 된다

**🔴 결제·구독 화면에는 넣지 않는다 (예외 없음)**
> 12장이 *"강제 결제 유도 없음"* 을 못 박았는데, **캐릭터로 결제를 설득하는 것은 같은 압박을 더 부드러운 얼굴로 하는 것**이다.
> 특히 44번(무료 플랜 유지 확인)에 토모를 넣으면 *"안 사서 아쉬워하는 것처럼"* 읽힐 수 있다. **무료를 고르는 것이 미안해지면 안 된다.**
> 우리 캐릭터는 **학습의 동반자이지 영업 사원이 아니다.**

### 14.3 비주얼 스타일 확정 — 외곽선 없는 플랫 블롭
제작 과정에서 3D 렌더, 두꺼운 검은 외곽선 스티커 스타일 등 여러 방향을 검토했으나, 최초 레퍼런스(랜딩페이지 시안)와 가장 일치하는 **외곽선 없는 부드러운 파스텔 블롭 형태**로 최종 확정. 이유: 브랜드 자산 전반의 통일성 확보, 앱 내 작은 아이콘으로 축소되어도 인식성 유지.

**예외적 활용**: 3D 렌더·두꺼운 외곽선 스타일은 장표 표지, 마케팅 캠페인 등 특별한 순간에 한해 별도 자산으로 제작 (일상적인 앱 UI에는 사용하지 않음)

### 14.4 캐릭터 성격·말투 확정 — "조용한 관찰자 토모"
초안 5종(`기획/character_bible_draft_01~05.md`) 검토 후 통합안을 확정. 상세 전문은 `기획/character_bible_최종안.md` 참조. (초안 문서들은 캐릭터명이 "토모"이던 시기의 기록 — 성격 설계는 그대로 유효하고 이름만 토모로 승계됨)

**한 줄 컨셉**: 말은 아끼지만 필요한 순간에 딱 맞는 한마디를 건네는 조용한 관찰자 — 시작엔 길을 짚어 주고, 틀릴 땐 기억해 주고, 돌아오면 새 표현을 슬쩍 내밀고, 오래 쉬었다 와도 이유를 묻지 않는다.

> **등불 정체성이 성격을 강화한다**: 토모가 말이 없는 이유가 설정에서 자연히 도출된다 — 등불은 소리치지 않고 빛으로만 존재하기 때문. "재촉하지 않음"도 마찬가지로, 등불은 끌지 않고 비출 뿐이다.

**구성 방식**: 성격은 하나(과묵한 관찰자)로 고정하고, 바뀌는 것은 절제된 말 한마디의 '결'뿐이다.

| 순간 | 얹는 태도 | 근거 |
|---|---|---|
| 기본 말투(베이스) | 조용한 관찰자 — 짧고 절제, 적은 말수, 낮은 리액션 | 흐름을 끊지 않음(PRD 1.2) |
| 온보딩 | 든든한 길잡이(시작점을 짚어 줌) | 코스 자유 전환의 방향 안내(PRD 10.4) |
| 오답 | 기억해 주는 세심함 | 오답 패턴 기반 조언(PRD 8.2) |
| 재접속(오카에리) | 새 표현 향한 조용한 호기심 | 콘텐츠 매력(설문 Q5) |
| 복귀(오래 쉬고) | 이유 묻지 않는 담담함 | 이탈 1위 "바빠서"(PRD 3장) 대응 |

**핵심 특질**: ①과묵함/절제(베이스) ②세심한 관찰력 ③결정적 한마디(남발 안 함) ④순간에 맞는 색 ⑤재촉·판단 없음.

**말투 규칙**: 짧은 문장, 적은 말수, 한 화면 한두 마디, 느낌표·수식어 최소. 당위("~해야 해요") 대신 허용("~해도 돼요"). 명령·독촉·놀림 금지.

**상황별 말투 샘플** (등불 정체성 반영)
- 온보딩: "토모예요. 말은 많이 안 할게요. 어디부터 볼지, 제가 비춰 둘게요."
- 오답: "여기, 지난번에도 걸렸던 곳이에요. 기억해 뒀어요. 이번엔 한 번 더 봐요."
- 재접속: "왔네요. …그새 새 표현이 좀 쌓였어요. 하나, 보러 갈래요?"
- 복귀: **"오랜만이에요. 불은 켜 둔 채였어요."** ← 등불이기에 가능한 말. 이유를 묻지 않으면서 기다렸음을 전한다
- 학습 독려(비독촉): "오늘은 여기까지만 해도 돼요. 한 거, 제가 다 봤어요."
- 우표 적립: "오늘 몫, 다 하셨네요. 우표 한 장이요."

**표정·비추기**: 비추는 대상 매핑은 14.2 그대로. 베이스 표정은 "조용히 지켜보는 잔잔한 눈"이고, **감정은 주로 밝기로 표현**한다. 성격·형태는 어느 코스에서도 불변.

### 14.5 토모의 쪽지 — 용기를 주는 일본어 문장 (Should)

**왜 필요한가**: 핵심 철학은 *"학습 의지를 꺾지 않고 **북돋아 준다**"* 인데, 지금까지의 설계는 전부 "꺾지 않는다"(강제·마찰 제거)에만 해당했다. **북돋는 장치가 없었다.** 이 기능이 그 자리를 채운다.
또한 현재 앱에 들어오려면 반드시 *학습 세션*을 해야 하는데, 이 콘텐츠는 **학습하지 않는 날의 재방문 경로**를 만든다 — 이탈 1위 "바빠서·귀찮아서"(35%, 3장)에 대한 새로운 대응.

| 항목 | 확정 내용 |
|---|---|
| 이름 | **토모의 쪽지** |
| 형식 | **보기 전용** (따라 쓰기는 이후 단계) |
| 범위 | **전 코스 동일** — 코스와 무관한 공통 콘텐츠 |
| 진입 | **홈에서 토모를 탭** + 새 쪽지가 있으면 **토모가 살짝 밝아짐** |
| 보상 | **없음 (우표 미지급)** |
| 해석 | **기본 제공(ON)** |
| 우선순위 | Should |

**"편지"와 "쪽지"의 구분 (중요)**
| | 편지 | 쪽지 |
|---|---|---|
| 무엇 | **토모의 이정표 편지**(일본어 본문 + 후리가나·해석, 그 기간을 담담히 회고) | 격려 문장(일본어) |
| 받는 법 | **우표 마일스톤**(첫 편지 3장·이후 14장, 12.2) | 그냥 열림 |
| 성격 | 소장용 + **읽기 학습**(긴 개인 편지, 편지함에 쌓임 8.3) | 가볍게 보고 지나감(짧은 한 줄) |
→ 무게 차이가 두 콘텐츠의 성격 차이와 일치한다. **우표→편지 리워드 논리(12.2)가 훼손되지 않도록** 격려 콘텐츠에는 "편지"를 쓰지 않는다.
> **v2.9 개정**: ①편지는 더 이상 요약 PDF가 아니다(우표 컬렉션 모델, 12.2). 요약 PDF는 우표와 무관한 결과물(무료 월 5회, 12.1)로 분리됐고, 편지는 **토모의 감성 편지**다. ②**편지 본문 = 일본어 + 후리가나(기본 ON)·해석(기본 OFF, 우상단 토글)** — 편지도 학습이 되게(대표님 2026-07-31). 편지·쪽지 둘 다 일본어이나 편지는 「긴 개인 편지(우표 마일스톤·소장)」, 쪽지는 「짧은 격려 한 줄(무료)」로 구분. ③도착은 홈 우표 위젯이 「편지 도착」으로 알린다(밝기 헤일로는 쪽지 전용 14.2.1 유지).

**보상을 주지 않는 이유**: 우표를 지급하면 *"용기를 얻으러 여는 것"* 이 *"보상 파밍"* 이 된다. 보상이 없어야 **"학습 실적이 아니라 쉼표"** 라는 정체성이 지켜진다.

**해석을 기본 노출하는 이유 (8.4 원칙의 예외)**: 8.4는 *"먼저 스스로 부딪히는 면은 읽기 도움 기본 OFF"* 인데, 이 화면은 **부딪히는 자리가 아니라 위로받는 자리**다. 못 읽고 좌절하면 목적 자체가 무너지므로 해석을 기본 제공한다. (원칙과 충돌이 아니라 원칙의 적용 범위 밖)

**발견성 설계**: 배지·빨간 점 같은 압박 장치를 쓰지 않고, **등불이 밝아지는 것**으로 새 쪽지를 알린다. 캐릭터 컨셉(14.2 밝기=표정)을 그대로 UI 신호로 쓰므로 홈에 상시 요소가 늘지 않는다.

**콘텐츠 원천 (저작권 안전 원칙 적용)**: 속담·관용구(ことわざ, 저작권 없음) / 青空文庫 저작권 만료 문학의 한 구절 / 자체 창작 문장(일본인 채용 후 감수). ⚠️ 현대 작가 명언·인용문은 저작권 리스크가 커서 사용하지 않는다.
