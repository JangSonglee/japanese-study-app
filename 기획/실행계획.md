## 0. 이 계획의 전제 두 가지

**① 기능 스코프는 줄이지 않는다** (PRD 11.0)
코스 5개, 퀴즈 6종, PDF 4종 전부 Must로 확정됐다. 그래서 출시를 앞당기는 수단은 **"줄이기"가 아니라 "순서"** 뿐이다.

**② 무거운 것은 기능이 아니라 콘텐츠다**
기능은 한 번 만들면 5개 코스가 공유한다. 콘텐츠는 코스마다 따로 채워야 한다.
→ **기능을 먼저 완성하고, 콘텐츠는 3개 코스만 채워 출시**한다.

---

## 1. 🔴 먼저 봐야 할 것 — 진짜 병목은 콘텐츠가 아니라 "감수"다

계획을 짜면서 나온 문제다. **콘텐츠 3개 코스 중 비즈니스가 막혀 있다.**

| | 상태 |
|---|---|
| 설문 관심도 | **비즈니스·JLPT 공동 1위 (30%)** |
| 리서치 결과 | 비즈니스 **전 영역 `⚠️검증필요`** — 현지 실사용·세대/업계 적합성 미검증 |
| 확정된 규칙 | **일본인 감수 전까지 확정·출시 금지** (코스별 검토 11번) |

즉 **비즈니스 콘텐츠의 완료 시점 = 일본인 감수자를 구하는 시점**이고, 이건 우리가 코드로 당길 수 없다.
경어·접대·교섭 표현은 틀리면 **그냥 오류가 아니라 실례**가 되므로 이 규칙을 완화할 수도 없다.

**→ 대표님 판단이 필요한 갈림길 (아래 5장 A안/B안)**

## 2. 전체 흐름

```
Phase 0  착수 준비        ─┬─ 아토: Hi-fi 40화면
(병렬 3트랙)                ├─ 도다이: schema.sql + RLS
                           └─ 슈슈: 콘텐츠 제작 규격 + 파일럿
                                    ↓
Phase 1  뼈대 세우기       Expo 셋업 · 디자인 토큰 코드화 · 공통 컴포넌트
                                    ↓
Phase 2  🔴 수직 슬라이스   JLPT N3 단어 탭 하나만 "끝까지" 관통
                           온보딩→학습→퀴즈→오답→우표→편지→PDF
                                    ↓
Phase 3  가로 확장         나머지 탭·코스·화면·퀴즈 유형
                                    ↓
Phase 4  콘텐츠 채우기     JLPT · 여행회화 (· 비즈니스)
                                    ↓
Phase 5  QA · 스토어 출시
```

## 3. Phase별 상세

### Phase 0 — 착수 준비 (병렬) · 예상 3~4주

세 트랙이 서로를 기다리지 않는다. **지금 바로 동시에 돌릴 수 있다.**

| 트랙 | 담당 | 산출물 | 크기 | 완료 판정 |
|---|---|---|---|---|
| **A. Hi-fi 나머지** | 아토 | 40화면 (현재 11/52) | **L** | 52화면 전부 컬러·타이포 적용, 다크 모드 대비 실측 통과 |
| **B. DB 구축** | 도다이 | `schema.sql` + RLS 정책 | **M** | 로컬에서 마이그레이션 실행 성공, 더미 유저로 격리 확인 |
| **C. 콘텐츠 규격** | 슈슈 | 콘텐츠 입력 포맷 정의 + **JLPT N3 단어 100개 파일럿** | **M** | 파일럿 데이터가 스키마에 그대로 들어감 |

> ⭐ **C가 조용한 지뢰다.** 콘텐츠 포맷을 정하지 않고 제작을 시작하면 나중에 수천 건을 다시 만져야 한다.
> "N3 단어 100개"를 실제로 스키마에 넣어보는 **파일럿**이 반드시 먼저다. 100개에서 나는 문제가 2,250개에서도 똑같이 난다.

**Phase 0에서 확정해야 할 것**
- 급수별 목표 단어 수 (수집형 진행률 **분모**) — 스키마_설계 6장 ③
- 구독 증정 우표 350장 지급 시점 — 스키마_설계 6장 ④
- 청해 음성 제작 방식 (TTS / 성우 / 혼합) ← **아직 아무도 정하지 않았다**

### Phase 2 — 🔴 수직 슬라이스 · 예상 4~5주

**JLPT N3 단어·어휘 탭 하나만 고르고, 그것만 끝까지 관통한다.**

```
온보딩(4문항) → 홈 → 코스 상세 → 단어 카드 10개 → 퀴즈(객관식)
→ 오답 분기 → 오답노트 저장 → 우표 1장 → 오늘의 편지 → PDF 다운로드
```

**왜 이 방식인가**
- 52화면을 가로로 다 만들면 **마지막 통합에서 터진다.** 1인 개발에서 이건 치명적이다.
- 하나를 끝까지 뚫으면 **설계 오류가 지금 드러난다** — 우표 적립 타이밍, PDF 생성 위치, 오답노트 상태 전이 같은 것들.
- 이 슬라이스가 돌면 **나머지는 같은 패턴의 복제**가 된다.

**완료 판정 (여기가 중요)**
- [ ] 실기기에서 온보딩부터 PDF 다운로드까지 **끊김 없이 통과**
- [ ] 우표가 **서버에서** 발급된다 (앱이 원장에 직접 못 씀을 확인)
- [ ] 오답 2회 연속 → 분기 노출 / 정답 2회 연속 → "이제 알아요" 전이
- [ ] PDF에 **진행률·우표·D-day가 들어가지 않음** (PRD 8.2.1)
- [ ] 후리가나 켜고 끌 때 **레이아웃이 점프하지 않음**

## 4. 크리티컬 패스

**가장 오래 걸리는 사슬은 이것이다:**

```
콘텐츠 규격(P0-C) → 파일럿 → 대량 제작 → 감수 → 검수 → 탑재
```

개발이 아니라 **콘텐츠**가 크리티컬 패스다. 그래서:
1. **Phase 0의 C 트랙을 오늘 시작한다** (가장 먼저 착수해야 할 것)
2. 콘텐츠 제작은 **Phase 1~3 내내 병렬로** 돌린다
3. 감수자 확보는 **지금부터 알아본다** — 구하는 데 걸리는 시간이 곧 출시 지연

## 5. 🔴 대표님 판단이 필요한 갈림길

### 갈림길 ① — 비즈니스 코스를 MVP에 넣을 것인가

| | **A안 — 3개 코스로 출시 (현행 계획)** | **B안 — 2개 코스로 먼저 출시** |
|---|---|---|
| MVP 콘텐츠 | JLPT · 여행회화 · **비즈니스** | JLPT · 여행회화 |
| 비즈니스 | 함께 출시 | "곧 열려요" → 감수 후 업데이트 |
| 장점 | 설문 1위 수요를 처음부터 잡음 | **감수 일정에 출시가 인질로 잡히지 않음** |
| 단점 | **감수자를 못 구하면 출시 전체가 밀림** | 1위 수요 코스가 초기에 비어 있음 |
| 리스크 | 🔴 우리가 통제할 수 없는 변수 | 🟡 통제 가능 |

> **PM 의견**: 감수자를 **먼저 알아보고**, 8월 안에 확보되면 A안, 아니면 B안으로 가는 **조건부 결정**을 권합니다.
> 지금 확정할 필요가 없고, 확정하면 오히려 손해예요. 뉴스·전래동화를 "곧 열려요"로 두기로 한 것과 **같은 논리**입니다.

### ✅ 갈림길 ② — 청해 음성 — **해소됨 (2026-07-23)**

**전량 TTS 확정. 성우 녹음 없음.** 실제로 만들어 듣고 판정했다.

- **고저 악센트**(箸/橋·雨/飴)가 **구분됨** → 관문 통과
- **촉음·`ん`·장음** 정확 → 단어·예문·받아쓰기는 TTS로 충분
- **간투사**만 어색했으나 **대본 표기 `えーと……。`** 로 해결 (`콘텐츠_입력규격.md` 4.4.1)

> **비용은 애초에 논점이 아니었다** — MVP 12만 자는 어느 서비스의 무료 한도로도 덮인다.
> 성우를 쓰지 않는 진짜 이유는 **수정 가능성**이다. 콘텐츠가 계속 바뀌는 초기에 녹음본은 한 글자 고치려면 스튜디오를 다시 잡아야 한다.

**남은 선택(작음)**: Azure로 바로 갈지, 결제 등록 후 Google 상위 등급까지 비교할지.
상세 = `리서치/청해_음성_제작_검토.md`

### 갈림길 ③ — Phase 2를 어느 탭으로 뚫을 것인가

현재 계획은 **JLPT 단어 탭**. 이유는 수집형·회독형 중 **단순한 쪽**이고 카드 UI가 가장 많이 재사용되기 때문.
다만 **여행회화**로 뚫으면 메인 페르소나(여행러 지은) 경험을 더 빨리 확인할 수 있다.

> **PM 의견**: JLPT 단어 탭 권장. 여행회화는 **스피킹 퀴즈(TTS·마이크 권한)** 가 물려 있어 첫 관통에는 변수가 많아요.
